# LinuxOps Web — установка на новый сервер

## Что нужно

- **ОС:** AlmaLinux / RHEL 10 (проверено) или 9, x86_64. Отдельная ВМ — сервис ставит nginx на 80/443 и свою службу.
- **Ресурсы:** 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска плюс место под записи сеансов (по умолчанию до 20 ГБ, задаётся в ⚙).
- **Сеть при установке:**
  - репозитории ОС и EPEL — оттуда nginx, sqlite, openldap, guacd;
  - OpenH264 и PowerShell 7 лежат в архиве релиза, их интернет не нужен.
- **Сеть при работе:**
  - SSH (22) и RDP (3389) до управляемых хостов;
  - LDAPS (636) до контроллеров AD;
  - для сверки CVE — HTTPS наружу с сервера (можно через прокси).
- **Доступ:** root или sudo.

.NET на сервер ставить не надо: среда выполнения уже внутри релиза. Её исправления безопасности приезжают с новым релизом, `dnf update` их не трогает. То же с SQLite.

## Откуда берутся сборки

Готовые сборки лежат в репозитории, как у MK Adm: папка `releases/linuxops-web` в ветке `feature/linuxops-web`:
- архив `LinuxOps.Web-<версия>-linux-x64.tar.gz` (через Git LFS);
- файл `.sha256` к нему;
- `LATEST` — номер последней версии.

В папке хранятся последние 5 версий. Сборка попадает туда только по отдельной команде — `.\tools\package-linuxops-web.ps1 -Publish`. Обычная сборка и выкладка на стенд её не трогают.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/MerlKoryAmber/MKIdea/feature/linuxops-web/src/LinuxOps.Web/deploy/get.sh | sudo bash
```

Скрипт читает `LATEST`, скачивает архив, сверяет сумму и запускает `install.sh`. Варианты:
- конкретная версия и ключи установщика — `… | sudo bash -s -- --version 0.7.3 --no-firewall`;
- только проверить источник, ничего не ставя, — `… | sudo bash -s -- --check`;
- свой источник (внутренний GitLab) и токен на чтение — через окружение:

  ```bash
  curl -fsSL <адрес get.sh> | sudo LINUXOPS_WEB_RAW_BASE=https://gitlab.local/<группа>/<проект>/-/raw/<ветка>/releases/linuxops-web LINUXOPS_WEB_TOKEN=<токен> bash
  ```

  Источник и токен запоминаются для обновлений.

Если сервис уже стоит, `get.sh` не ставит его повторно: обновление — через меню.

## Установка из архива (без доступа к репозиторию)

1. Скопировать на сервер `LinuxOps.Web-<версия>-linux-x64.tar.gz` и `.sha256` — из `releases/linuxops-web` или `dist\`.
2. Проверить и распаковать:

   ```bash
   sha256sum -c LinuxOps.Web-<версия>-linux-x64.tar.gz.sha256
   tar -xzf LinuxOps.Web-<версия>-linux-x64.tar.gz
   ```
3. Установить:

   ```bash
   sudo ./LinuxOps.Web-<версия>/deploy/install.sh
   ```

Ключи `install.sh` (и `get.sh`):
- `--no-guacd` — без шлюза сессий: не будет терминала, RDP и записей;
- `--no-firewall` — не трогать firewalld.

Установщик ставит пакеты, заводит пользователя службы `linuxops-web` и учётку консоли `linuxops-ps`, выпускает самоподписанный сертификат, настраивает nginx, файрвол (http и https), службу и команду `linuxops-web`. В конце печатает адрес.

## После установки

1. Задать пароль локального админа — без него войти нельзя: `sudo linuxops-web` → `9` → «Set password». TOTP привязывается при первом входе — по QR-коду в приложении-аутентификаторе.
2. Открыть `https://<сервер>/` и войти под `admin`.
3. Дальше свой пароль локальный админ и локальные пользователи меняют сами: щелчок по имени в шапке. Нужны текущий пароль и код TOTP. Если пароль забыт: у пользователя его задаёт админ в ⚙ → «Учётки», у локального админа — меню на сервере.

## После первого входа

Всё — в ⚙:
1. **Вход** — AD: контроллеры, LDAPS, домен, учётка поиска. «Проверить соединение» и «Проверить вход». Здесь же MK 2FA, если он есть.
2. **Права** — назначить роли группам AD: на «всё», на папку или на хост.
3. **Inventory** — хосты и папки, ключи или пароли SSH; подтвердить ключи хостов.
4. **Проверка уязвимостей** — расписание «Версий ПО».
5. **Записи сеансов** — срок и объём. Там же «Где хранить»: сетевая папка SMB, NFS или отдельный диск сервера. Сервер всё подключает сам; руками на сервере ничего делать не нужно (см. ниже).

Сертификат: `sudo linuxops-web` → `8`. Там есть запрос CSR для своего УЦ и загрузка подписанного сертификата или PFX.

## Где что лежит

| Что | Где |
|---|---|
| Программа (релизы, текущий — ссылка `current`) | `/opt/linuxops-web/` |
| Данные: база, аудит | `/var/lib/linuxops-web/` |
| Записи сеансов: буфер (пишет guacd) | `/var/lib/linuxops-web-rec/` |
| Записи сеансов: хранилище (SMB, NFS, диск — если подключено) | `/var/lib/linuxops-web-archive/` |
| Модули PowerShell (PowerCLI) | `/var/lib/linuxops-web-ps/` |
| Мастер-ключ и ключ консоли | `/etc/linuxops-web/` |
| Бэкапы | `/var/backups/linuxops-web/` |
| Служба | `linuxops-web.service` (+ `nginx`, `guacd`) |

Данные и мастер-ключ установка и обновление не трогают никогда. Бэкап содержит мастер-ключ, поэтому с сервера его копировать только в зашифрованном виде.

## Записи сеансов на отдельном хранилище

⚙ → «Записи сеансов» → «Где хранить»:
- **SMB** — путь `//сервер/папка`, учётка, домен, пароль. Пароль хранится только у root на сервере, в базу сервиса не попадает.
- **NFS** — `сервер:/экспорт`. На NFS-сервере нужно дать запись пользователю службы: uid и gid `linuxops-web` на этом сервере, либо `all_squash,anonuid=…,anongid=…`.
- **Отдельный диск** — диск добавляют ВМ, затем «Найти свободные диски». Подходит только пустой диск: без разделов и файловой системы. Сервис размечает его в XFS после подтверждения именем диска.

Сеансы пишутся сначала на сервер (буфер). Готовые записи раз в минуту переносятся в хранилище. Если хранилище недоступно, записи ждут в буфере, а в шапке у админа появляется «⚠ Записи». Если записывать некуда (в буфере меньше 1 ГБ), сеанс пускается без записи, и это попадает в аудит.

Пакеты `cifs-utils` и `nfs-utils` ставятся из репозиториев ОС при первом подключении. Состояние — в `sudo linuxops-web status`, строки Records и Storage.

## Обновление, откат, удаление

`sudo linuxops-web` — меню. То же одной командой:

```bash
sudo linuxops-web update                       # последняя версия из releases/linuxops-web (LATEST)
sudo linuxops-web update --version 0.7.3       # конкретная версия из той же папки
sudo linuxops-web update --file X.tar.gz       # из архива на сервере
sudo linuxops-web rollback                     # на предыдущую версию
sudo linuxops-web backup | restore [STAMP]
sudo linuxops-web uninstall | purge            # purge — вместе с данными
```

Если после обновления служба не поднялась, она сама возвращается на прежнюю версию.

Источник обновлений — `/etc/linuxops-web/release.conf`, параметр `RAW_BASE`. При переезде на внутренний GitLab меняется только он. Токен на чтение для закрытого репозитория задаётся в меню, пункт `7`. Обновление с 0.7.2 и раньше переписывает этот файл само, старый остаётся рядом как `release.conf.bak`.

## Если что-то не так

- `sudo linuxops-web status` — служба, nginx, guacd, версия, сертификат, Health.
- `sudo linuxops-web logs service` — журнал службы; `logs audit` — аудит.
- RDP не подключается — проверьте, что стоит `openh264` (из комплекта) и что guacd активен.
- Вкладка PowerShell не открывается — `status`: должен быть pwsh; PowerCLI ставится в ⚙ → «PowerShell и PowerCLI».
