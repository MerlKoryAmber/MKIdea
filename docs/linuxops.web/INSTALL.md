# LinuxOps Web — установка на новый сервер

## Что нужно

- **ОС:** AlmaLinux / RHEL 10 (проверено) или 9, x86_64. Отдельная ВМ — сервис ставит nginx на 80/443 и свою службу.
- **Ресурсы:** 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска плюс место под записи сеансов (по умолчанию до 20 ГБ, задаётся в ⚙).
- **Сеть при установке:**
  - репозитории ОС и EPEL — оттуда nginx, sqlite, openldap, guacd;
  - OpenH264 и PowerShell 7 лежат в архиве релиза, их интернет не нужен.
- **Сеть при работе:**
  - SSH (22) и RDP (3389) до управляемых хостов;
  - LDAPS (636) до контроллеров AD;
  - для сверки CVE — HTTPS наружу с сервера (можно через прокси).
- **Доступ:** root или sudo.

.NET на сервер ставить не надо: среда выполнения уже внутри релиза. Её исправления безопасности приезжают с новым релизом, `dnf update` их не трогает. То же с SQLite.

## Установка

1. Скопировать на сервер два файла релиза: `LinuxOps.Web-<версия>-linux-x64.tar.gz` и `.sha256`. Они лежат в релизе Git с тегом `linuxops-web-v<версия>` или в `dist\` после `tools\package-linuxops-web.ps1`.
2. Проверить и распаковать:

   ```bash
   sha256sum -c LinuxOps.Web-<версия>-linux-x64.tar.gz.sha256
   tar -xzf LinuxOps.Web-<версия>-linux-x64.tar.gz
   ```
3. Установить:

   ```bash
   sudo ./LinuxOps.Web-<версия>/deploy/install.sh
   ```

   Ключи:
   - `--no-guacd` — без шлюза сессий: не будет терминала, RDP и записей;
   - `--no-firewall` — не трогать firewalld.

   Скрипт ставит пакеты, заводит пользователя службы `linuxops-web` и учётку консоли `linuxops-ps`, выпускает самоподписанный сертификат, настраивает nginx, файрвол (http и https), службу и команду `linuxops-web`. В конце печатает адрес.
4. Задать пароль локального админа — без него войти нельзя:

   ```bash
   sudo linuxops-web
   ```

   В меню: `9` → «Set password». TOTP привязывается при первом входе — по QR-коду в приложении-аутентификаторе.
5. Открыть `https://<сервер>/` и войти под `admin`.

## После первого входа

Всё — в ⚙:
1. **Вход** — AD: контроллеры, LDAPS, домен, учётка поиска. «Проверить соединение» и «Проверить вход». Здесь же MK 2FA, если он есть.
2. **Права** — назначить роли группам AD: на «всё», на папку или на хост.
3. **Inventory** — хосты и папки, ключи или пароли SSH; подтвердить ключи хостов.
4. **Проверка уязвимостей** — расписание «Версий ПО».
5. **Записи сеансов** — срок и объём.

Сертификат: `sudo linuxops-web` → `8`. Там есть запрос CSR для своего УЦ и загрузка подписанного сертификата или PFX.

## Где что лежит

| Что | Где |
|---|---|
| Программа (релизы, текущий — ссылка `current`) | `/opt/linuxops-web/` |
| Данные: база, аудит, записи сеансов | `/var/lib/linuxops-web/` |
| Мастер-ключ и ключ консоли | `/etc/linuxops-web/` |
| Бэкапы | `/var/backups/linuxops-web/` |
| Служба | `linuxops-web.service` (+ `nginx`, `guacd`) |

Данные и мастер-ключ установка и обновление не трогают никогда. Бэкап содержит мастер-ключ, поэтому с сервера его копировать только в зашифрованном виде.

## Обновление, откат, удаление

`sudo linuxops-web` — меню. То же одной командой:

```bash
sudo linuxops-web update                       # последний релиз из Git (токен — пункт 7)
sudo linuxops-web update --file X.tar.gz       # из архива на сервере
sudo linuxops-web rollback                     # на предыдущую версию
sudo linuxops-web backup | restore [STAMP]
sudo linuxops-web uninstall | purge            # purge — вместе с данными
```

Если после обновления служба не поднялась, она сама возвращается на прежнюю версию.

## Если что-то не так

- `sudo linuxops-web status` — служба, nginx, guacd, версия, сертификат, Health.
- `sudo linuxops-web logs service` — журнал службы; `logs audit` — аудит.
- RDP не подключается — проверьте, что стоит `openh264` (из комплекта) и что guacd активен.
- Вкладка PowerShell не открывается — `status`: должен быть pwsh; PowerCLI ставится в ⚙ → «PowerShell и PowerCLI».
