1. Первый вход и порядок настройки

  1. На сервере задайте пароль локального админа: sudo linuxops-web → 9 → «Set password».
  2. Откройте https://<сервер>/ и войдите под admin. При первом входе привяжите TOTP: отсканируйте QR-код в приложении-аутентификаторе.
  3. Дальше настройка в ⚙, по порядку: Вход (AD) → Права → Inventory → Проверка уязвимостей → Сеансы и записи.

Разделы настроек слева. Обычный пользователь видит только «Внешний вид».

2. Вход: AD, сессия, второй фактор

  • Вход через AD. Укажите контроллеры, защиту, порт, домен, где искать (DN) и учётку поиска с паролем. Защита: LDAPS (636) или StartTLS (389). Вариант «Без шифрования» — только для лаборатории: пароли пойдут по сети открытым текстом.
  • Проверить соединение проверяет связь с контроллером и учётку поиска. Проверить вход проверяет логин и пароль конкретного человека: кто он и какие роли получит.
  • Сессия. «Простой, минут» — выход при бездействии. «Всего, часов» — общий срок входа.
  • Второй фактор для AD — MK 2FA. Вход подтверждается в приложении MK 2FA. Локальный админ и локальные пользователи входят с TOTP.

3. Учётки: локальный админ и пользователи

  • Локальный админ (admin) управляется только с консоли сервера: sudo linuxops-web → 9. Там пароль, сброс TOTP, вкл/выкл. Это запасной вход на случай, если AD недоступен.
  • Локальные пользователи — для тех, у кого нет учётки в домене. Заполните логин, имя, пароль (не короче 12 символов) и нажмите Завести. Права задаются в «Правах» как назначение «локальному». Свой пароль пользователь меняет сам, щелчком по имени в шапке. Если пароль забыт, его задаёт админ здесь.

4. Права: роли и назначения

4.1. Роли

Роль — набор прав. Встроенные роли изменить нельзя. Свою роль можно создать (Новая роль) или сделать на основе встроенной (Копировать).

ПравоЧто даёт
просмотрВидеть хосты, результаты и историю.
уязвимостиВкладка Vulnerabilities по своим хостам.
Dry-runОпрос и Dry-run, только чтение на хостах.
ПрименитьИзменения на хостах: обновления, пользователи, прокси.

Чтобы дать дежурному смотреть идущие сеансы, но не закрывать их, сделайте копию нужной роли и отметьте в ней только «Сеансы: смотреть». Назначьте эту роль на «всё».

4.2. Назначения

Назначение — это кто, с какой ролью и на что. «Кто»: группа AD, человек из AD, локальный пользователь или сервис API. «На что»: «всё», папка (с вложенными) или хост. У человека из нескольких групп права складываются. Изменения действуют сразу, в том числе у тех, кто уже вошёл.

  • Роль «Админ» назначает и снимает только админ.
  • Назначение на папку удобнее делать прямо в Inventory: правая кнопка по папке → Доступ… (см. раздел 5).

5. Inventory: хосты и папки

  • + Хост Linux, + Хост Windows, + vCenter, + Папка — добавить в выделенную папку.
  • Изменить (или двойной щелчок), Дублировать, Удалить.
  • Щелчок по треугольнику сворачивает папку. Правая кнопка открывает меню.
  • Переместить в папку… в меню хоста или папки — выбрать, куда переложить. Если хост отмечен галкой в Actions вместе с другими, переезжают все отмеченные. То же можно сделать мышью: перетащить хост или папку на папку (на хост — в его папку, на «Сюда — в корень» — в корень).
  • Нужно право «Inventory» на то, что перекладываете (для папки — там, где она лежит), и на папку назначения. Папку нельзя положить в её же подпапку. Назначения, выданные на папку, после переезда действуют по новому месту; в аудите — «откуда → куда».
  • Ключ SSH: загрузите файлом (Файл…) или выберите из уже сохранённых. Сохранённый ключ привязан к адресу хоста: на другой адрес его не подставить.
  • Проверить подключение покажет ключ хоста. Подтвердите его: без подтверждения сервис к хосту не подключится. Если ключ хоста изменился, подключения блокируются, пока ключ не подтвердят заново.
  • Пароли и ключи хранятся на сервере в зашифрованном виде и в браузер не возвращаются: поле пустое — значит «не менять».

6. Импорт из CSV и учётка SSH на много хостов

Импорт…

Загрузите CSV в UTF-8 до 2 МБ. Разделитель — точка с запятой, запятая или табуляция, сервис определит сам. В Excel сохраняйте как «CSV UTF-8». Шаблон — кнопка Скачать шаблон. Колонки:

  • имя и адрес — обязательные;
  • тип — linux (по умолчанию) или windows;
  • порт — по умолчанию 22 или 3389;
  • папка — путь через «/», например Отдел А/Web; недостающие папки будут созданы;
  • логин — пользователь SSH (для Linux).

Сервис покажет итог по каждой строке («добавить», «уже есть», «ошибка»). Добавить N сохраняет только строки «добавить». Пароли и ключи в CSV не задаются: для этого есть «Учётка SSH…».

Учётка SSH…

Задаёт логин и ключ (или пароль) сразу многим хостам Linux. Отметьте хосты слева (фильтр, «Все», «Снять»; выделенная папка — все её хосты). Справа укажите логин, вход и ключ, sudo. Пустое поле означает «не менять». Всё применяется одной транзакцией: Применить к N.

7. Проверка уязвимостей и выход в интернет

  • Проверять ежедневно в заданное время, например 03:00. Проверка запускает «Версии ПО» по всем хостам Linux, результаты попадают во Vulnerabilities.
  • Списки обновлений — через сервер (туннель SSH): для хостов без интернета — на время проверки хост ходит к репозиториям через сервер и его прокси (порты 80 и 443). Такой туннель могут заметить SIEM / EDR — включайте по согласованию с ИБ.
  • CVE сверяются всегда: сервер ходит в базы Red Hat, NVD, CISA KEV, EPSS и в endoflife.date (последние выпуски). Наружу уходят только имена пакетов, версии и номера CVE, без адресов и имён хостов. Ответы кэшируются на сутки.
  • Окна «Параметры действий» у расписания нет — параметры берутся отсюда. Во Vulnerabilities такие строки помечены «расписание».
  • Проверить сейчас — запуск вне расписания. Ниже — когда был последний запуск и сколько хостов проверено.

Пороги «закрыть сейчас»: CVE есть в CISA KEV, или EPSS ≥ 10 %, или CVSS ≥ 9 при атаке по сети.

Выход в интернет

⚙ → Выход в интернет — HTTP-прокси, через который сервер ходит наружу: сверка CVE, последние выпуски и туннель «через сервер». Настройки системы (/etc/environment, прокси dnf) служба не использует: если интернет только через прокси, задайте его здесь, иначе базы не ответят и проверка покажет «прокси сервера не задан».

  • Прокси — адрес и порт, например proxy.corp.local:3128. Логин и пароль не поддерживаются. Пусто — напрямую.
  • Кроме — имена и маски через запятую, к ним напрямую (*.corp.local, 10.1.2.3). Локальные адреса — всегда напрямую.
  • Проверить связь — запросы к NVD, EPSS и endoflife.date по сохранённой настройке; их видно в журнале прокси. Изменение действует сразу, без перезапуска, и пишется в аудит.
  • В ⚙ → «PowerShell и PowerCLI» поле прокси для установки PowerCLI заполняется отсюда.

8. Сеансы и записи: предел, срок, хранилище

  • Одновременные сеансы — сколько терминалов, RDP и консолей PowerShell может быть открыто у одного человека сразу, во всех окнах браузера вместе. Просмотр чужого сеанса не считается. 0 — без предела. Отказ по пределу записывается в аудит («сеанс: отказ — предел»).
  • Хранить, дней и Не больше, ГБ. Раз в час удаляются записи старше срока, а затем самые старые, пока объём не уложится в лимит. Идущий сеанс не удаляется. Значение 0 — без ограничения. Почистить сейчас запускает очистку сразу.
  • Записывать нажатия клавиш — по умолчанию выключено: так в записи не попадают набранные вслепую пароли.
  • Где хранить: сетевая папка SMB, NFS или отдельный пустой диск сервера. Сервер подключает их сам. Сеансы сначала пишутся в буфер на сервере, раз в минуту готовые записи переносятся в хранилище.
Если хранилище недоступно, записи ждут в буфере, а в шапке появляется ⚠ Записи. Если в буфере осталось меньше 1 ГБ, сеанс пускается без записи, и это попадает в аудит. Если хранилище отключить, записи в нём перестанут открываться. Проигрыватель скажет: «файла нет — удалена по сроку или лежит в отключённом хранилище».

9. History → Аудит

Кнопка Аудит в History доступна с правом «аудит». Здесь видно, кто, когда и с какого адреса что сделал: входы и выходы, запуски, изменения Inventory и настроек, открытия терминалов и RDP, просмотр и скачивание записей, просмотр вживую, закрытие сеансов администратором.

10. History → Сеансы: идущие, просмотр, записи

10.1. Идут сейчас

Вверху «Сеансов» — таблица идущих терминалов, RDP и консолей PowerShell: начало, вид (SSH, RDP, PS), хост, кто подключён и сколько человек смотрит (👁). Таблица обновляется каждые 5 секунд. Блок виден с правом «сеансы: смотреть» или «сеансы: закрывать».

10.2. Смотреть вживую

Смотреть открывает справа экран идущего сеанса. Это только просмотр: ваши клавиатура и мышь в сеанс не передаются. Пользователь не видит, что за ним смотрят. Факт просмотра записывается в аудит («сеанс: просмотр вживую»). ⛶ Весь экран разворачивает экран, Перестать смотреть закрывает просмотр. Переход на другие вкладки сервиса просмотр не закрывает; проигрыватель записи при этом встаёт на паузу.

10.3. Закрыть сеанс

Закрыть → подтверждение Да. Сеанс обрывается. У пользователя появится «отключено: сеанс закрыт администратором». В журнале сеансов статус будет «закрыт администратором: <кто>». Запись сеанса сохраняется.

11. PowerShell и PowerCLI

Вкладка PowerShell — консоль pwsh на самом сервере, под отдельной учёткой linuxops-ps, с модулем VMware PowerCLI. Доступна только роли «Админ». Сеанс записывается, как терминал.

В ⚙ → PowerShell и PowerCLI показаны версии. Модули можно скачать из интернета через прокси (Скачать из интернета) или поставить из архива без интернета (Установить из ZIP…: архив модулей с ПК, где есть PowerShell Gallery). Удалить модули убирает установленные модули.

12. Сервисы API

Сервисная учётка нужна внешней системе, например SIEM или инвентаризации ПО. Она запускает встроенные действия только на чтение («Проверить обновления», «Версии ПО» и другие) и получает результат. Учётка заводится с именем и назначением, токен показывается один раз. Права задаются в «Правах» как назначение «сервису API». Описание API — в docs/linuxops.web/API.md.

13. Обслуживание сервера

Все команды выполняются на сервере через sudo linuxops-web …. Без аргументов команда открывает меню.

КомандаЧто делает
statusСлужба, nginx, guacd, версия, сертификат, записи и хранилище.
updateОбновиться до последней версии из releases (--version X — до конкретной, --file X.tar.gz — из архива).
rollbackВернуть предыдущую версию.
backup / restore [STAMP]Бэкап базы, аудита и мастер-ключа / восстановление.
logs service / logs auditЖурнал службы / аудит.
меню → 8Сертификат: запрос CSR для своего УЦ, загрузка подписанного или PFX.
меню → 9Локальный админ: пароль, TOTP, вкл/выкл.
Перед обновлением сделайте backup. Бэкап содержит мастер-ключ, которым открываются все сохранённые пароли и ключи, поэтому копируйте его с сервера только в зашифрованном виде. Данные и мастер-ключ обновление не трогает.

Кто сейчас подключён к хостам, видно в History → Сеансы → «Идут сейчас». Перед обновлением имеет смысл проверить этот список: обновление перезапускает службу и обрывает идущие сеансы.
