# LinuxOps Web — скелет

## Проекты

| Проект | Что |
|--------|-----|
| `src/LinuxOps.Core` | ядро, общее с настольной версией (net8.0): SSH, план, каталог, «Версии ПО», CVE, обновление, учётки, прокси, история. Пространства имён прежние (`LinuxOps.Services`, `LinuxOps.Models`) |
| `src/LinuxOps.Web` | Blazor Server (net8.0), одна страница `/`, рендер `InteractiveServer` без пререндера |
| `src/LinuxOps` | настольная WPF-версия, ссылается на ядро |

## Связь ядра с интерфейсом

- `IUserPrompts` (`UserPrompts.Current`) — вопросы ядра: пароль ключа, доверие ключу хоста, пароль sudo. Настольная — `WpfPrompts` (окна), веб — `WebPrompts`: через `AsyncLocal<PromptChannel>` вопрос попадает в окно браузера, которое запустило действие; фоновый поток ждёт ответа до 10 минут.
- `CrashLog` — запись в ядре; окно и ловушка нативных падений — `CrashReporter` настольной версии.
- `LINUXOPS_DATA_DIR` — каталог данных ядра (known_hosts, кэш CVE, свои действия). Веб задаёт его в `WebPaths.Prepare()`.
- `HostConfig.PrivateKeyText` — ключ текстом, только в памяти (из хранилища сервиса).

## Сервис

- `Program.cs` — пути, `WebPrompts`, DI: синглтоны `SecretBox`, `WebStore`, `AuditLog`, `HostLocks`, `GuacTickets`, `GuacLive`, `FileDownloads`, `FleetCheck`, `RecordingsKeeper` (обе и фоновые службы), `ApiJobs`, `PsConsole`; на окно браузера — `PromptChannel`, `UiDialogs`, `WebSession`. `UseWebSockets` → `/guac/tunnel`. До всего — `RunPlace.Server()` (тексты ядра «через сервер LinuxOps Web», `LinuxOps.Core/Services/RunPlace.cs`).
- `WebStore` — SQLite (WAL): `folders`, `hosts` (JSON без секретов; хост Windows — `DistroHint = "windows"`, `StoredHost.IsWindows`), `secrets` (зашифровано), `history`, `audit`, `settings`, `sessions` (сеансы guacd), `fleet` (последний итог «Версии ПО» по хосту). `ForConnect` — копия хоста с расшифрованными секретами, только для подключения.
- `SecretBox` — AES-256-GCM, `v1:` + base64(nonce|tag|шифр); мастер-ключ 32 байта, создаётся при первом запуске (права 600).
- `AuditLog` — база + `audit.log` + syslog.
- `HostLocks` — замок на `хост:порт` на время действия.
- `WebSession` — перенос `ActionsViewModel`: выбор хостов и плана, предпросмотр, запуск (строки RUN, живой вывод, время), опрос, «Добавить пользователя», «Обновить отмеченное», хосты и папки.
- `UiDialogs` — стек модальных окон с `TaskCompletionSource` (как `ShowDialog`).

## Вход и права (`Services/Auth`)

- `LoginService` — шаги входа: пароль → (локальный админ или локальный пользователь, `ITotpAccount`) TOTP или привязка по QR; AD → группы и назначения (нет назначений — не пускает) → MK 2FA, если включён. Локальный пользователь проверяется раньше AD. Пауза после 5 неудач. `Resolve` по `UserKind` (`local` — админ, `user` — локальный, `ad`) — назначения перечитываются при открытии окна и на каждом запросе; группы — из cookie (`grp`, с момента входа). `LoginService.Password.cs` (0.7.3) — `CanChangeOwnPassword`, `ChangeOwnPassword`: свой пароль локального админа или локального пользователя — текущий пароль + код TOTP (шаг TOTP сдвигается, повтор кода не пройдёт), неудачи — в общий счётчик пауз; лабораторный режим — только сервер. Окно — `PasswordDialog.razor` из шапки (`Shell`, имя — кнопка).
- `LoginService.Mfa.cs` — ожидание MK 2FA в памяти (`MfaPending`: пользователь, challenge, `context` попытки): `StartMfa`, `PollMfa`, `CodeMfa`, `CancelMfa`; пускает только `consume` 200 с тем же логином и `context`. `MkMfa` — клиент API MK 2FA (Bearer, `Idempotency-Key`, `Probe` — опрос несуществующего запроса).
- `AuthEndpoints` — POST `/auth/login`, `/auth/totp`, `/auth/mfa/poll` (JSON, вход прямо в ответе), `/auth/mfa/code`, `/auth/mfa/cancel` (и sendBeacon при уходе), `/auth/logout` (антиподделка), cookie `lo.auth`; «ждём код» (логин или `mfa:номер`) и сообщение — защищённые cookie. `Validate` — простой, общий срок, учётка включена, роли есть. `/auth/ping` — продление из открытого окна (`App.razor`). Страница MK 2FA — `wwwroot/login-mfa.js`.
- `LdapAuth` — bind учёткой пользователя, группы через `member:1.2.840.113556.1.4.1941:`; `Probe` — rootDSE анонимно. На Linux подсказывает загрузчику `libldap.so.2`. `Find` — поиск групп и людей учёткой поиска из настроек (`AdLookupUser`, пароль зашифрован), до 25 строк.
- `Totp` (RFC 6238; `QrDataUri` — QR-код PNG через QRCoder), `PasswordHash` (PBKDF2-SHA256, 600 000), `AuthModels` — модель как в vSphere: `Perm` (14 прав; `Global` — аудит, настройки, vCenter, Inventory, «сеансы: смотреть» и «сеансы: закрывать» — только из назначения на «всё»; `AdminOnly` — vCenter), `Role` — только набор прав (встроенные: admin, operator, auditor, viewer; не меняются), `Assignment` — кто (группа AD, человек AD или локальный — `Local`) → роль → объект (`Scope` all / folder / host); `Matches` учитывает вид входа: назначение AD не действует на локального с тем же логином. `Grant`, `UserInfo` (`Can` — право где-нибудь, `Limited`), `LegacyRole` — для переноса, `AuthSettings` (AD, сессия, MK 2FA: адрес, секрет зашифрован, текст), `LocalAdmin`, `LocalUser` (пароль, TOTP, вкл/выкл).
- `AdminCli` — `LinuxOps.Web admin status | password [--generate] | totp-reset | enable | disable | lab on|off` (лаба: admin/admin без TOTP, плашка «ЛАБА»); меню сервера зовёт его через `runuser -u linuxops-web`.
- `WebStore.Auth.cs` — настройки `auth`, `local_admin` (секрет TOTP зашифрован `SecretBox`), таблицы `roles` (свои роли), `assignments` и `local_users` (удаление — вместе с назначениями); `LoadTotpAccount` / `SaveTotpAccount` — админ или локальный по логину. Перенос ролей до 0.4.0 (группы и папки внутри роли) в назначения — один раз, флаг `auth_model=2`. 0.7.2: свои роли с `hosts.view` получают `fleet.view` один раз (`GrantFleetView`, флаг `perm_fleet=1`). Удалили папку или хост — их назначения тоже.
- `WebSession.Access.cs` — `User`, `Can` (где-нибудь), `CanOn` (хост: «всё», сам хост, папка выше), `CanOnFolder` (папка или выше; корень — только «всё»); отказ с аудитом и сообщением (`Notice` — поверх любой вкладки); видимые хосты и папки (`ApplyFolderScope`); `AllHostsAllowed` — запуск только если право есть на каждом отмеченном хосте. Папки: создать — право на родителя, переименовать — на саму, удалить — на родителя.
- Страницы: `Login.razor` (статическая, без WebSocket), `Home.razor` (`[Authorize]`, форма выхода, `lo-idle`), `SettingsTab.razor` — открывается шестерёнкой в шапке (вкладки нет): боковое меню разделов (`Sections`, раздел в `sessionStorage` `lo.settings.section`); без права «Настройки» — только тема. Панели разделов: `MfaPanel`, `LocalUsersPanel`, `ApiClientsPanel`, `PsPanel`, `RightsBlock` (роли и назначения).

## Publish

`dist\LinuxOps.Web-<ver>\` — linux-x64 self-contained, рядом `LinuxOps.Web-<ver>-linux-x64.tar.gz` + `.sha256` (`tools/package-linuxops-web.ps1`: до сборки — уязвимые NuGet-пакеты (стоп, обход `-AllowVulnerable`) и SHA-256 guacamole из `wwwroot/lib/guacamole/SOURCE.txt`; после — .NET внутри против последнего исправления .NET 8). .NET внутри закреплён в csproj: `LinuxOpsRuntimePatch` → `KnownFrameworkReference.LatestRuntimeFrameworkVersion`. Документы: `README.md`, `INSTALL.md`, `API.md`.

## Сервер (`deploy/`)

- `lib/common.sh` — пути, ввод (`/dev/tty` или stdin), сертификаты (свой CA с `nameConstraints`), источник релизов (GitHub / GitLab API), `activate_release` (`restorecon` релиза и данных — иначе служба в `init_t`; переключить `current`, поднять, при неудаче вернуть прежний).
- Свои стили и скрипты подключаются с версией в адресе (`WebPaths.Asset`) — после обновления не берутся из кэша браузера.
- `install.sh` (`--upgrade` из update), `update.sh`, `uninstall.sh` (`--purge`), `linuxops-web.sh` — меню; `/usr/bin/linuxops-web` — обёртка на `current/deploy/linuxops-web.sh`. `get.sh` (0.7.3) — установка одной командой из `releases/linuxops-web` (LATEST → архив → `.sha256` → `install.sh`; `--version`, `--check`; `LINUXOPS_WEB_RAW_BASE`, `LINUXOPS_WEB_TOKEN`). Источник обновлений — `release.conf` (`CONF_REV=2`, `PROVIDER=repo`, `RAW_BASE`; старый — `.bak`), `release_find` / `release_download` / `release_probe` / `release_where` в `lib/common.sh`; `github` и `gitlab` (раздел Releases) остались вариантами. Сборки в репозитории — `releases/linuxops-web` (Git LFS, `.gitattributes`), кладёт `tools/package-linuxops-web.ps1` (последние 5).
- `VERSION` пишет publish (цель `WriteDeployVersion` в csproj).
- На сервере: `/opt/linuxops-web/releases/<ver>`, `current`, `previous`; `/var/lib/linuxops-web` — данные; `/etc/linuxops-web` (root:linuxops-web 0750, служба только читает; `etc_dir_ensure`) — мастер-ключ, `release.conf`, `git-token`, учётка SMB; `/etc/pki/linuxops-web` — сертификат и CA; `/var/backups/linuxops-web` — бэкапы.
- С ПК на стенд — `tools/deploy-linuxops-web.ps1 -Target stand`.

## Сеансы, файлы, парк (0.5.0)

- `Services/Guac/` — `GuacProtocol` (кодирование «длина.значение», длины в кодовых точках), `GuacTickets` (одноразовый пропуск на 60 с: параметры connect, только тому же пользователю), `GuacTunnel` — `/guac/tunnel` (WebSocket, подпротокол `guacamole`): рукопожатие с guacd (`select` → `args` → `size`/`audio`/`video`/`image`/`timezone` → `connect`), служебная первая инструкция с номером сеанса, ping — эхом, отправка в WebSocket под замком; `sessions` и аудит; `/guac/recording/{id}` — запись (`.guac`) или текст терминала без управляющих символов, только с правом «аудит»; `kind=gaps` — паузы записи (> 5 с без рисования) для «Пропускать простой». `GuacLive` — идущие сеансы (`LiveSession`: кто, хост, `ConnectionId` из `ready`, зрители, `Kill`), `IsPowerShell`, `Ended` (владелец ушёл — зрители отключаются: guacd держит соединение, пока подключён хоть кто-то); предел на человека — `TryReserve`/`Release` (место от подключения к guacd до конца сеанса, настройка `sess.limit`): владелец сеанса регистрируется в туннеле; пропуск с `WatchId` — зритель: `select <ConnectionId>` с `read-only=true`, к guacd пропускаются только `sync`, `ack`, `nop`, `disconnect`, без записи и `SessionStart`; `Close` — браузеру `error … 523`, затем обрыв, статус «закрыт администратором: кто». `WebSession.Live.cs` — `CanSeeLive`, `WatchSession` (право `sessions.watch`), `CloseSession` (`sessions.close`), аудит.

Записи — `WebPaths.RecordingsDir` (`/var/lib/linuxops-web-rec`, guacd:linuxops-web 2770, `recordings_dir_ensure` в `deploy/lib/common.sh`; там же `openh264_ensure DIR` — RPM из `DIR/deploy/vendor` под версию ОС (подпись EPEL, `rpm -K`), иначе репозиторий `epel-cisco-openh264`; `dnf swap noopenh264`: без неё FreeRDP 2 в guacd не подключает RDP. ## API и PowerShell (0.7.0)

- `Services/Api/ApiEndpoints` — `MapGroup("/api/v1")`, без cookie и антиподделки, Bearer-токен: `/openapi.json` (файл `wwwroot/api/openapi.json`), `/actions`, `/hosts`, POST и GET `/jobs`, `/jobs/{id}` (чужое — 404); ошибки `{"error":{code,message}}`; неверный токен — аудит не чаще раза в минуту на адрес. Вид входа `UserKind.Api`, назначения `Assignment.Api`. Документ для интеграторов — `docs/linuxops.web/API.md`.
- `Services/Api/ApiJobs` — запуск: только `ActionDefinition.ReadOnly && !Destructive && !IsPowerShell` (поле `ReadOnly` — в ядре, `BuiltinActions`), только объявленные параметры, 1–50 хостов с правами «просмотр» и «Dry-run» на каждом, до 3 идущих на учётку; фон: `HostLocks`, `PlanRunner` с `apply:false`, Pre-flight → поле `connect`, History, `SaveFleet`, аудит от `api:<имя> (адрес)`. Модели `ApiJob`, `ApiHostResult` (JSON snake_case, кириллица без `\u`).
- `ApiClient` (`AuthModels`) — имя, описание, вкл/выкл, `TokenHash` (SHA-256 токена `lo_` + 32 байта base64url), подсказка, создан, последний вход. `WebStore.Api.cs` — таблицы `api_clients`, `api_jobs` (хранятся 7 дней), поиск по хешу через `FixedTimeEquals`; удаление учётки снимает её назначения.

- `Services/Auth/Access` — `Under`, `CanOn` без окна браузера (общие для `WebSession.Access` и API).
- `PsConsole` — статус (версия pwsh, версия `VMware.VimAutomation.Core` в каталоге модулей), PowerCLI из PowerShell Gallery (`Save-PSResource`, прокси переменными окружения) или из ZIP (папки модулей с `Имя.psd1`), удаление модулей; pwsh от сервиса — `-NoProfile`, без телеметрии; одна установка за раз.
- `WebSession.Sessions.OpenPowerShell` — право vCenter (только «Админ»), пропуск guacd на SSH `127.0.0.1` под `WebPaths.PsUser` ключом `WebPaths.PsKey`, ключ хоста — из `/etc/ssh/ssh_host_*_key.pub` по порядку libssh2; запись и текст терминала как у терминала; в сеансах — «PowerShell (сервер)».
- `deploy/lib/common.sh`: `pwsh_ensure DIR` (RPM из `deploy/vendor`), `ps_account_ensure` — учётка `linuxops-ps` с оболочкой `/usr/local/libexec/linuxops-ps-shell`, пароль заблокирован, ключ ed25519 (создаётся один раз), `authorized_keys` с `from=…,restrict,pty`, профиль (каталог модулей первым в `PSModulePath`), настройка PowerCLI с CEIP=False (если файла ещё нет), каталог модулей `linuxops-web:linuxops-ps` 2750, `restorecon`. `uninstall.sh --purge` убирает учётку, модули и оболочку; юнит — `ReadWritePaths=-/var/lib/linuxops-web-ps`. RPM pwsh кладёт в релиз `tools/package-linuxops-web.ps1` (`$vendorPkgs`, закреплённый SHA-256).
