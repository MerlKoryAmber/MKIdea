# LinuxOps Web — CURRENT

**Версия:** 0.5.0 · ветка `feature/linuxops-web` · план — `docs/linuxops/PLAN-web.md`

## Отложено
- **Ф4, остаток:** второй фактор через API MK 2FA (вход и подтверждение опасных действий); QR-код при привязке TOTP (нужна библиотека QRCoder — на согласовании); сертификат в «Настройках» (пока — меню на сервере); простой внутри открытого окна считается по мыши и клавишам в браузере.
- **RDP:** рабочий стол не проверен входом с правом RDP на хост (у тестовой учётки его нет на DC). RPM OpenH264 в комплекте только для EL10 x86_64; на EL9 — из репозитория (нужен доступ к CDN Cisco).
- **Файлы:** без создания папок, удаления и переименования (урезанно по решению); загрузка — через соединение окна (до 1 ГБ).
- **В вебе пока нет:** «Закрыть доступ», «Базовые пользователи», свои действия («Новое»), PowerShell / vCenter. Кнопки есть, но выключены с подсказкой.
- **API для внешних сервисов** — Ф8 плана, после входа и ролей.
- Тексты галок «через этот ПК» и «с этого ПК» в действиях ядра — в вебе это сервер; поправить, когда ядро будет знать, где оно запущено.

## 0.5.0
- **Подключения (Ф3):** терминал SSH и RDP в браузере через guacd.
  - **SSH:** под учёткой хоста из Inventory (пароль или ключ), право «Терминал» на хост. Перед сеансом сервис сам проверяет ключ хоста (новый — спросит, как в Actions) и передаёт guacd проверенный ключ того типа, который выберет guacd (ECDSA → Ed25519 → RSA). Ctrl+V и Shift+Insert вставляют буфер ПК, выделенное в терминале попадает в буфер ПК.
  - **RDP:** хосты Windows — «+ Хост Windows» в Inventory (имя, адрес, порт, «Проверить порт»). Вход — своей доменной учётной записью (`DOMAIN\user`, `user@domain` или логин — домен из настроек AD; вошли через AD — логин подставлен). Пароль живёт только в пропуске на 60 с и уходит в guacd, нигде не хранится. NLA, сертификат RDP не проверяется (в домене он самоподписанный), GFX выключен. guacd из EPEL собран на FreeRDP 2, а он без настоящей OpenH264 не подключается вовсе (в EL10 — заглушка `noopenh264`): RPM `openh264` (сборка Cisco, подпись EPEL) лежит в релизе, `deploy/vendor`, — установка и обновление ставят его сами, без сети и ручных шагов (`openh264_ensure`: проверка подписи `rpm -K`, `dnf swap noopenh264`). Решение владельца: класть в дистрибутив (патентное покрытие Cisco действует только для загрузки с её сервера — при распространении своими силами вопрос лицензии H.264 на нас). Ответы guacd переведены: неверная учётка или пароль; пароль принят, но нет права входа по RDP на хост; хост не отвечает.
  - Пароли и ключи в браузер не уходят: окно выдаёт одноразовый пропуск (60 с, только этому пользователю), туннель `/guac/tunnel` сам делает рукопожатие с guacd.
  - Хосты Windows лежат в общем дереве и папках, права назначаются так же; Actions, опрос, терминал и файлы их пропускают.
- **Записи сеансов:** каждый сеанс пишется (экран — `.guac`, у SSH ещё текст терминала). History → «Сеансы» (право «аудит»): кто, куда, когда, итог; запись проигрывается с перемоткой, текст терминала скачивается без управляющих символов. Просмотр и скачивание — в аудите. Каталог `/var/lib/linuxops-web-rec` (guacd:linuxops-web, 2770; в юните службы — `ReadWritePaths`) создаёт установка и обновление. Сеансы, оборванные перезапуском службы, помечаются «прерван».
- **Хранение записей** (⚙ → «Записи сеансов»): срок в днях (по умолчанию 90) и предел объёма в ГБ (по умолчанию 20; 0 — без ограничения). Чистка раз в час и после сохранения, плюс «Почистить сейчас»: сначала старше срока, потом самые старые, пока каталог не уложится. Идущий сеанс и файлы свежее 5 минут не трогаются. У сеанса в журнале — «запись удалена: …», чистка — в аудите от «хранение записей». Галка «Записывать нажатия клавиш» (по умолчанию выкл.: пароли, набранные в сеансе, попали бы в запись); плеер нажатия не показывает — они в файле `.guac`.
- **Экран сеанса** вписывается в окно (при масштабе Windows больше 100 % guacd делает рабочий стол RDP крупнее окна). Окно и плеер — со своим контекстом наложения: основной холст Guacamole с `z-index: -1`, иначе RDP (рисует в него) уходил под фон — «чёрный экран, бегает мышь».
- **F5** оставляет на той же вкладке (запоминается в `sessionStorage` вкладки браузера; недоступная по правам — не открывается).
- **SSH Files (урезанно):** одна панель — папки хоста по SFTP, имена владельцев, путь вводом, «Скачать» (одноразовая ссылка, поток прямо с хоста), «Загрузить…» в текущую папку до 1 ГБ (есть такой файл — спросит, заменить ли). Права: «Файлы: чтение» — смотреть и скачивать, «Файлы: запись» — загружать. Скачивание и загрузка — в аудите.
- **Сводка по парку (Ф2+):** History → «Парк» — последняя проверка «Версии ПО» каждого хоста: когда и кто, «закрыть сейчас» (CVE в KEV, EPSS ≥ 10%, CVSS ≥ 9 по сети), обновления (из них безопасности), внимание; по хосту — только срочное. Наполняется любым запуском «Версии ПО» (Actions, «Обновить отмеченное», расписание). Видны только свои хосты.
- **Проверка парка по расписанию:** ⚙ → «Проверка парка по расписанию» — ежедневно в заданное время «Версии ПО» по всем хостам Linux, сверка CVE через сервер по галке; «Проверить сейчас». Запуск — в History и аудите от имени «расписание»; занятые хосты пропускаются; новый ключ хоста — отказ (спросить некого). Включили позже времени запуска — первый раз завтра; служба была выключена во время запуска — догонит в тот же день.
- **Правая кнопка по хосту** в «Подключениях» и SSH Files — как у списка хостов настольной версии: «Подключить» и «Открыть» в соседнем инструменте (терминал ↔ файлы, хост открывается сразу).
- **Ядро:** `SftpBrowser` — скачать в поток и загрузить из потока; строка результата плана несёт свой хост (`PlanProgress.Host`).

## 0.4.0
- **Права как в vSphere.** Роль — только набор прав. Назначение — «кто (группа или человек AD) → роль → объект (всё, папка, хост)». Назначение на папку действует на всё внутри. Одна группа может быть оператором в одной папке и смотреть другую. Роли и группы, заданные в 0.3.x, переносятся в назначения сами при первом запуске.
- **Новые права:** терминал SSH, RDP, файлы — чтение, файлы — запись (сами вкладки — на своих этапах). vCenter и PowerShell — только встроенная «Админ». Аудит и настройки действуют только из назначения на «всё».
- **Встроенные роли** (не меняются): Админ — всё; Оператор — просмотр, Dry-run, Применить, Inventory, терминал, RDP, файлы; Аудитор — просмотр, Dry-run, чтение файлов, аудит; Просмотр — только видеть.
- **Права проверяются на объекте:** запуск — только если право есть на каждом отмеченном хосте (иначе отказ со списком); хост — добавить в папку, где есть «Inventory», менять и удалять — с правом на сам хост. **Закрыта дыра с папками:** раньше пользователь с «Inventory» мог переименовать, удалить или создать любую папку; теперь — создать внутри своей, переименовать свою, удалить — с правом на родителя. Кнопки Inventory включены ровно по правам на выделенное.
- **«Доступ…»** (правая кнопка в Inventory) — назначения на объект: свои (можно убрать), от папок выше и «на всё»; «Назначить» — группа или человек из AD + роль. В «Настройках» — роли (только права) и общий список назначений с формой «кто — роль — на что».
- **Вкладки по правам:** SSH Files — с чтением файлов, Подключения — с терминалом или RDP, PowerShell — только админ.
- Учётка AD без назначений не входит («нет доступа к LinuxOps Web»). Сообщение сервиса об отказе теперь видно на любой вкладке, а не только в результатах Actions.
- Вход: в cookie — группы AD (раньше — роли); после обновления с 0.3.x пользователи AD входят заново.

## 0.3.2
- **Доступ правой кнопкой в Inventory:** у папки и хоста меню — изменить, дублировать, хост или папку внутрь, «Доступ…», удалить. «Доступ…» (право «Настройки») показывает, какие роли видят объект (сами, через папку выше или «все хосты»), галкой выдаёт и снимает; «Дать доступ» — найти группу или человека в AD, выбрать права (оператор, запуск, проверка, просмотр) — роль создаётся или дополняется сама. Роль без права менять Inventory и без «Настроек» меню не видит, окно правки хоста ей не открывается.
- **Роли ограничиваются и отдельными хостами**, не только папками. Видны хост и путь папок к нему.
- **Поиск в AD вместо ввода по памяти:** в настройках входа — учётка поиска (только чтение каталога, пароль зашифрован); в редакторе ролей и в «Доступ…» группы и люди ищутся по части имени, выбранные — плашками. Не нашлось — Enter добавляет как есть.
- **Галки папок в Actions:** папка отмечается, только если отметили её саму; отмеченные внутри хосты — черта «частично» (щелчок по ней отмечает всю папку).
- **Обрыв связи:** вместо серого окна «Could not reconnect» — полоска сверху «переподключаюсь…»; служба перезапустилась (обновление) — страница перезагружается сама, вход сохраняется.
- Уже вошёл — `/login` открывает главную. History у ограниченной роли пишет «по вашим хостам».
- **Ядро (и настольная версия):** хост с ключом, но без ключа — «ключ SSH не задан…» вместо «ключ не найден: » с пустым путём; подтверждали ключ хоста дольше таймаута — подключение повторяется само; таймаут — по-русски.

## 0.3.0
- **Вход** (Ф4): страница входа, без неё сервис не открывается (кроме самой страницы и стилей).
  - **Локальный админ** `admin` — аварийный вход: пароль (PBKDF2-SHA256) + свой TOTP по RFC 6238. При первом входе — привязка: секрет текстом и ссылка `otpauth://`. Пароль, новый TOTP, включить и выключить — только на сервере: `linuxops-web` → 9 «Local admin». После установки выключен, пока не задан пароль.
  - **Лабораторный режим** (только лаба): `linuxops-web admin lab-on` (меню «Local admin» → 6) — `admin` / `admin` без TOTP, красная плашка «ЛАБА» в шапке и на странице входа, каждый вход в аудите «без TOTP». `lab-off` или новый пароль — режим снят. На стенде включён.
  - **AD** через LDAP: вход учёткой пользователя, группы с вложенностью, роль — по группам или по логину. LDAPS, StartTLS или (только лаба) без шифрования.
  - Пауза 15 минут после 5 неудач на логин или адрес; между паролем и кодом — 5 минут; одноразовые коды.
  - Сессия: простой (по умолчанию 30 минут) и общий срок (10 часов); ключи cookie в каталоге данных — перезапуск службы не выкидывает. Выключенный админ или удалённая роль — выход при следующем запросе.
- **Роли:** встроенные «Админ», «Оператор», «Аудитор» и свои (новая, копия). Права: видеть хосты, опрос и Dry-run, применять, Inventory, аудит, настройки. Роль можно ограничить папками хостов — тогда видны только они, их история и запуск.
- **Права проверяются дважды:** кнопки выключены, и сервис отказывает сам (с записью «отказ: нет права» в аудит).
- **Вкладка «Настройки»** (право «Настройки»): вход через AD с кнопками «Проверить соединение» и «Проверить вход» (покажет группы и роли), сессия, роли, состояние локального админа.
- **В шапке** — кто вошёл и его роли, кнопка выхода. В аудите и истории — логин и адрес.
- **Тестовые учётки AD без человека:** `tools/lab/` — разовый `Initialize-LabAd.ps1` (владелец) создаёт OU=LinuxOps-Lab и служебную svc-lo-lab с keytab на стенде; дальше агент сам: `ssh stand lab-ad user|group|member|del|ls`. Пароли тестовых учёток — `/root/lab/test-accounts` на стенде.
- На AlmaLinux 10 LDAP из .NET 8 ищет `libldap-2.5.so.0`, а в системе `libldap.so.2` (OpenLDAP 2.6) — сервис подсказывает загрузчику нужное имя сам.

## 0.2.0
- **Установка и меню на сервере** (Ф0+, по шаблону 2fa `docs/patterns/cli-menu-linux.md`):
  - `deploy/install.sh` — первая установка одной командой: пакеты (nginx, firewalld, guacd из EPEL, jq, sqlite), пользователь, служба, nginx с TLS (свой CA сервера, если сертификата нет), файрвол;
  - `deploy/update.sh` — из релиза Git (GitHub, потом GitLab: `/etc/linuxops-web/release.conf`), по версии или из файла; проверка `.sha256`; служба не поднялась — сам возвращает прежнюю версию;
  - `deploy/uninstall.sh` — удаление с данными или без (purge — два подтверждения), бэкапы не трогает;
  - команда `linuxops-web`: меню и те же действия подкомандами — обновление, откат, удаление, токен Git, сертификат (свой CA, PEM, PFX, CSR для корпоративного CA), статус, старт и стоп, журналы, бэкап и восстановление, адрес.
- **Раскладка:** релизы в `/opt/linuxops-web/releases/<ver>`, текущий — ссылка `current`; откат — переключение ссылки. Хранятся текущий, предыдущий и ещё один.
- **Релиз:** `tools/package-linuxops-web.ps1` → `dist/LinuxOps.Web-<ver>-linux-x64.tar.gz` + `.sha256`, тег `linuxops-web-v<ver>`. `tools/deploy-linuxops-web.ps1` ставит его на стенд с ПК.

## 0.1.0
- **Первый веб на общем ядре** (Ф1 и Ф2 плана, Ф2+ без стенда).
  - **Ядро** вынесено в `LinuxOps.Core`. Настольная версия 0.3.54 работает на нём же, поведение не менялось.
  - **Сервис** — Blazor Server на .NET 8, одна страница. Вид — как у настольной версии: шапка, вкладки, три колонки Actions, подвал с планом, тёмная и светлая темы (⚙, запоминает браузер).
  - **Inventory:** хосты Linux и папки. Ключ SSH загружается файлом. Ключ и пароль хранятся в базе сервиса зашифрованными (AES-256-GCM, мастер-ключ отдельно) и в браузер не возвращаются.
  - **Actions:** «Опросить», план, Dry-run / Применить / Стоп, живой вывод строки RUN, «Детали» с таблицами (аудит учёток, прокси, «Версии ПО» с CVE), «Обновить отмеченное» (предпросмотр → подтверждение → установка → перезапуск служб → повторная проверка), «Добавить пользователя».
  - **Вопросы во время запуска** (ключ хоста, пароль sudo или ключа) приходят окном в то окно браузера, которое запустило действие.
  - **Блокировка хоста:** пока на хосте идёт действие, второй запуск получает «занят: кто, что, с какого времени».
  - **History** — общая для всех пользователей, с колонкой «Кто». Не стирается. Рядом — «Аудит».
  - **Аудит** — база (только дописывается) + `audit.log` + syslog (`logger -t linuxops-web`). На стенде без входа «кто» — адрес клиента.
- **Где данные.** Linux: `/var/lib/linuxops-web` (права 700) и `/etc/linuxops-web/master.key` (права 600). Windows (разработка): `data\` и `data-key\` рядом с программой. Пути меняются переменными `LINUXOPS_WEB_DATA` и `LINUXOPS_WEB_KEY`.
- **Адрес:** по умолчанию `http://127.0.0.1:5080`, меняется ключом `--urls`.
- **Релиз:** `dist\LinuxOps.Web-0.1.0` — linux-x64, self-contained, вместе с юнитом службы.
