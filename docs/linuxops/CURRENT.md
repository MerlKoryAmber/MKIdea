## 0.3.36
- Сессии терминала и SSH Files не засыпают: keepalive раз в 30 с на всех SSH-подключениях (терминал, SFTP, запуск действий) — межсетевые экраны и NAT больше не рвут простаивающее соединение.
- Терминал: обрыв со стороны сервера виден сразу — строка «[связь потеряна / сессия закрыта — Enter: подключиться снова]»; Enter подключает заново в той же вкладке, экран не стирается.
- SSH Files: обрыв SFTP — тихое переподключение при следующем действии (статус «связь восстановлена — повторите действие»), возврат в ту же папку.
- SSH Files, «Права: sudo» теперь работает и для просмотра: папку, закрытую своему пользователю (`/root`, `/root/.ssh` …), открывает и показывает от root (через sudo, с запросом пароля sudo). Без sudo — подсказка «Для чужих папок выберите «Права: sudo»». Выключили sudo в такой папке — возврат к своей.
- Поле пути в SSH Files: после неудачного перехода снова показывает текущую папку; не «залипает» на введённом тексте.
- Терминал: мышь для mc, htop, vim и т. п. — щелчки, двойной щелчок, колесо, перетаскивание отправляются программе, если она их запросила (xterm-режимы 1000/1002/1003, формат SGR 1006 и старый X10). С Shift — обычное выделение текста; правая кнопка — по-прежнему меню.
- Проверено на лабе: `cat -v` показывает точные клетки щелчка и колеса; в mc двойной щелчок по `.ssh` открывает папку, щелчок по «Quit» выходит; `kill -HUP $$` → строка обрыва → Enter → снова приглашение. SSH Files под временной lo-sudo (wheel): `/root` без sudo — отказ с подсказкой; с sudo — запрос пароля и список `/root`, вглубь `/root/.ssh` — `authorized_keys`; sudo выкл — домашняя папка; `pkill sftp-server` на сервере + «Обновить» — «связь восстановлена», список на месте. Учётка удалена.
- Ограничение: папку, закрытую своему пользователю, целиком не скачать — её содержимое разворачивается через SFTP. Отдельные файлы из неё скачиваются, просматриваются и правятся от root, как и раньше в режиме sudo.

## 0.3.32
- Зашифрованный SSH-ключ: при подключении LinuxOps спрашивает пароль ключа (окно «Пароль ключа SSH»). Пароль держится в памяти до закрытия приложения, на диск не пишется; запоминается по файлу ключа — хосты с одним ключом спросят один раз. Неверный пароль — повторный запрос с «Неверный пароль ключа.», до 3 попыток; «Отмена» — понятная ошибка. Раньше такой ключ не подключался вовсе («passphrase is empty»). Поле «Пароль» в режиме Key по-прежнему только для sudo.
- «Проверить подключение» в окне хоста больше не зависает на новом хосте: подключение идёт в фоне, окно «Доверять?» ключу хоста не ждёт занятый UI-поток.
- Окно запроса пароля (и sudo) подстраивает высоту под текст — после «Неверный пароль ключа.» поле ввода больше не обрезается.
- Проверено: ключи ed25519 / RSA (OpenSSH и PEM) / ECDSA — без пароля, с неверным и верным. На лабе (временный зашифрованный ed25519 в `authorized_keys`, после теста удалён): запрос → неверный → повтор → верный → «Подключено. CentOS Stream 9»; второе подключение — без запроса.

## 0.3.30
- «Закрыть доступ» рядом с «Добавить пользователя» (Actions → Хосты), на отмеченных хостах. Три режима:
  - «Заблокировать» (по умолчанию, обратимо): пароль закрыт (`usermod -L`), срок учётки истёк (`chage -E 0` — не пустит и по ключу, и в sudo), `authorized_keys` убран в сторону, снят из wheel/sudo/admin, файл sudoers LinuxOps убран, процессы пользователя завершены. Исходные хэш пароля, срок, ключи, группы и файл sudoers лежат в `/var/lib/linuxops/locked/<логин>` (только root).
  - «Отозвать ключ»: убрать один ключ (вставить строку или .pub) из `authorized_keys`; учётка и остальные ключи остаются. У заблокированного ключ убирается и из отложенных.
  - «Удалить учётную запись»: crontab, процессы, домашняя папка — в архив `/root/linuxops-removed/<логин>-<дата>.tar.gz` на том же хосте, затем `userdel -r`. Не удалось заархивировать — не удаляет. Чужую домашнюю папку не трогает. Кнопка активна только после ввода логина.
- «Открыть доступ…» в том же окне: вернуть пароль (тот же хэш), срок, ключи, группы и файл sudoers как были до блокировки. Снимает только блокировку LinuxOps.
- Сначала «Проверить» (только чтение): по каждому хосту «Сейчас» (активен/заблокирован, ключи, sudo, процессы) и «Будет сделано». Выполняется только там, где есть что делать.
- Не трогает root, системные учётки (uid < 1000) и учётку, под которой LinuxOps входит на хост; это проверяет и сам скрипт на сервере. Предупреждает о чужих правилах sudo (их не правит) и о том, что кроме этого пользователя sudo ни у кого нет.
- Базовые пользователи: после блокировки или удаления запись выключается, отозванный ключ убирается и из неё, чтобы «Применить» базовых пользователей не вернул доступ.
- Итоги в «Запуск плана» и в History.
- Исправлено: в редактируемых выпадающих списках не было видно вводимого текста (в шаблоне темы не было поля ввода).
- Проверено на лабе на одноразовых пользователях: блокировка (повторная тоже), возврат с тем же хэшем пароля, группой и ключами, отзыв одного ключа из двух, удаление с архивом при живом процессе, отказы для root, daemon, nobody и отсутствующего логина; через окно — все четыре действия.
