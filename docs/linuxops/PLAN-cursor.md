# LinuxOps — план доработок для Cursor

Проект: `src/LinuxOps` (WPF, .NET 8, SSH.NET). Текущая версия 0.3.3.

## Правила (для каждой задачи)

- Делай **только одну задачу** за раз. Следующую — только когда скажут.
- Трогай **только файлы, перечисленные в задаче**. Не переименовывай, не рефактори попутно, не меняй стиль кода в других местах.
- После задачи: `dotnet build` без ошибок и предупреждений; подними версию (patch) в `LinuxOps.csproj`; допиши строку в `docs/linuxops/CURRENT.md`.
- В отчёте перечисли: что изменено (файл:строка), что **не** сделано и почему. Не пиши «готово», если пункт не проверен.
- Не удаляй и не переписывай существующую функциональность, которая не упомянута в задаче.

## Задача 2. Sudo

Файлы: `Models/AppModels.cs`, `HostEditWindow.xaml(.cs)`, `Services/SshRunner.cs`, `MainWindow.xaml.cs`, новый `SudoPasswordWindow.xaml(.cs)`.

1. `HostConfig`: добавить `bool UseSudo` (по умолчанию true, если `Username != "root"`). В `HostEditWindow` — галочка «Выполнять через sudo».
2. При запуске действия с `Privilege = "sudo/root"` на хосте с `UseSudo` и не-root пользователем — выполнять через sudo.

5. Ошибку «sudo: a password is required» / «not in sudoers» показывать понятным текстом в строке результата.

**Проверка:** на хосте под не-root пользователем с sudo «Проверить обновления» проходит OK; пароль не появляется в `ps aux` на сервере во время выполнения.

## Задача 9. Карточка «Добавить пользователя»

Файлы: новый `AddUserWindow.xaml(.cs)`, новый `Services/UserProvisioning.cs`, `MainWindow.xaml(.cs)`, `Services/BuiltinActions.cs` (удалить `ensure-user-demo`).
Зависит от задачи 2 (sudo) и 8 (PlanRunner).

Форма, пользователь bash не пишет:

```
 Логин:      [ivanov        ]
 Права:      (•) sudo   ( ) обычный
 SSH-ключ:   [ ssh-ed25519 AAAA... ivanov@laptop ]  [Из файла…]
 Пароль:     [          ]  (пусто = вход только по ключу)

 Применить к выделенным хостам: srv-app-01, srv-db-01

                                  [Отмена]  [Добавить]
```

1. Кнопка «Добавить пользователя» в шапке панели «Хосты» (Actions). Применяется к отмеченным хостам.
2. Проверки в форме: логин `^[a-z_][a-z0-9_-]{0,31}$`; ключ — одна или несколько строк публичного ключа (`ssh-ed25519`, `ssh-rsa`, `ecdsa-sha2-*`, `sk-*`), base64 валиден; если вставлен **приватный** ключ (`-----BEGIN`) — отказ с понятным текстом. Показать SHA256-отпечаток ключа.
3. На каждом хосте (команды собирает C#, значения через переменные окружения, не вклеивать в текст скрипта):
   - создать пользователя, если нет (`useradd -m -s /bin/bash`);
   - sudo: добавить в `wheel` (rhel/suse) или `sudo` (debian) по определённому дистрибутиву;
   - `~/.ssh` 700, `authorized_keys` 600, владелец — пользователь; ключ добавить, только если такого ещё нет;
   - на rhel-семействе: `restorecon -R ~/.ssh` (если команда есть);
   - пароль, если указан: `chpasswd` через stdin, не в командной строке.
4. Скрипт возвращает итог строкой `key=value` (created=yes/no, sudo=added/already, key=added/already, password=set/skip); в результатах показывать по-человечески: «srv-db-01 — уже был, ключ добавлен».
5. Повторный запуск ничего не дублирует.
6. Выполняется через sudo (задача 2), если подключение не под root.
7. Встроенное действие `ensure-user-demo` («Пользователь и роль») удалить.

**Проверка:** на двух хостах (CentOS и Ubuntu) новый пользователь заходит по ключу `ssh -i key user@host`; повторный запуск — «уже есть», дубля ключа в `authorized_keys` нет.

## Задача 12. Доделки после 0.3.15

Файлы: `Services/UserProvisioning.cs`.

1. SUSE: по умолчанию в sudoers стоит `Defaults targetpw`, и sudo спрашивает пароль **root**, а не пользователя. В файл `/etc/sudoers.d/linuxops-<login>` перед правилом писать `Defaults:<login> !targetpw`.
2. Sudo под не-root пользователем ни разу не проверялся (лаба работает под root). Завести на лабе пользователя с sudo по паролю и пользователя с NOPASSWD, прогнать «Проверить обновления» и «Добавить пользователя» под каждым. Результат записать в отчёт.

**Проверка:** на openSUSE пользователь, заведённый с sudo, выполняет `sudo id` своим паролем; оба sudo-сценария на лабе проходят, пароль не попадает в History.
