# LinuxOps Web 0.7.4 — отчёт

Дата: 22.11.2026. Стенд: 192.168.0.169.

## Что сделано

Хранилище записей сеансов — из интерфейса, на сервере руками ничего (решения владельца от 22.11.2026: SMB, NFS и диск; буфер и перенос; без записи — пускать с тревогой; старые записи — оставить на месте).

1. ⚙ → «Записи сеансов» → «Где хранить»: SMB, NFS, отдельный диск. «Проверить», «Отключить».
2. Буфер и перенос: guacd пишет на сервер, готовые записи раз в минуту переносятся в хранилище (копия, сверка размера, удаление из буфера).
3. Проигрывание в History — из буфера или хранилища.
4. Нельзя записать (нет буфера или в нём меньше 1 ГБ) — сеанс идёт без записи, пометка в журнале сеанса и аудите.
5. Тревога «⚠ Записи» в шапке у тех, у кого «Настройки».
6. Монтирует помощник root: path-юнит по файлу-запросу (sudo из службы невозможен — `NoNewPrivileges`). Строка в fstab с пометкой.
7. `get.sh` и `update`: при 404 пишут «ничего не опубликовано», а не «нет сети».

## Найдено и исправлено по ходу

- NFS был `hard`: при пропаже сервера зависли бы ⚙ и проигрывание. Теперь `soft` (у SMB тоже) и проверка доступности хранилища в фоне не дольше 5 с, итог помнится 30 с.
- Неудачная попытка подключить другое хранилище снимала рабочее. Теперь помощник возвращает прежнее (строку fstab, файл учётки SMB, монтирование).
- Перенесённые файлы были 0644 — теперь 0640, как в буфере.
- Пометка сеанса («без записи») затиралась при закрытии — теперь сохраняется; после перезапуска службы — тоже.
- В ⚙ диск показывался как `UUID=…` — теперь имя устройства.

## Ограничения

- Хранилище одно: при переключении записи в прежнем перестают проигрываться (файлы там остаются) — в ⚙ предупреждение.
- Реальный второй диск ВМ не добавлялся (нет учётки vCenter в лабе): проверено на loopback-диске LIO — для системы это обычный SCSI-диск.
