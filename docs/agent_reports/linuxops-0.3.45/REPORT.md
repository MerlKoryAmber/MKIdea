# LinuxOps 0.3.45 — испорченный defaults.json не затирается

Дата: 2026-11-17 (МСК).

## Задача
Попутная находка из 0.3.44, владелец сказал «делай». Если `LinuxOps.defaults.json` не читался (ошибка в JSON после ручной правки, `null`, файл занят), `DefaultsStore.Load()` молча возвращал пустые настройки. Первое же сохранение (тема, план Actions, любое изменение Inventory) перезаписывало файл: хосты, папки и vCenter пропадали без следа.

## Изменения
`Services/DefaultsStore.cs`:
- **Ошибка в JSON или `null`:**
  - файл переименовывается в `LinuxOps.defaults.broken-<yyyyMMdd-HHmmss>.json` рядом с exe;
  - программа начинает с чистого файла;
  - в `Problem` записываются причина (строка и позиция в JSON) и путь к копии.
- **Файл не читается** (занят — 5 попыток по 100 мс; нет прав):
  - в `Problem` записывается причина;
  - включается режим «только чтение»: `Write` ничего не пишет до перезапуска.
- **Не удалось переименовать испорченный файл** — тоже режим «только чтение».
- **Атомарная запись:** сначала `LinuxOps.defaults.json.tmp`, потом `File.Move(..., overwrite: true)`. Оборванная запись не оставит полупустой файл.
- Текст причин — по-русски, без английских сообщений .NET.

`MainWindow.xaml.cs`: если `DefaultsStore.Problem` задан, после показа окна открывается `AppDialog.Info` с заголовком «Файл настроек». Это происходит один раз; первое чтение настроек — в `ThemeManager.Init`, до главного окна.

## ✅ Проверено
Проверял на копии Debug-сборки через UI Automation, без ввода с клавиатуры. Сохранение вызывал настоящим действием: «Настройки» → тема «Ночная» → «Отмена».
- **Испорченный JSON:**
  - окно «Файл настроек: испорчен (ошибка в JSON, строка 1, позиция 54)» с путём к копии;
  - копия совпадает с исходным файлом;
  - после смены темы создан новый `defaults.json`, копия цела, `.tmp` не осталось.
- **`null` в файле** — то же окно («в файле нет настроек (null)»), копия совпадает.
- **Файл занят** (открыт с FileShare.None):
  - окно «файл занят другой программой или недоступен… изменения не сохраняются»;
  - после освобождения файла и смены темы файл не перезаписан, хост `keep-me` на месте.
- **Исправный файл (регресс):**
  - окна нет;
  - после смены темы хосты (`keep-me`, `lab-centos`) сохранены, тема вернулась на «system».
- Сборка Debug и Release — без ошибок.
- **Smoke `dist\LinuxOps-0.3.45`** (копия в scratchpad):
  - версия 0.3.45;
  - на испорченном файле — то же окно.

## 👀 Не проверено
- Ревью не автором не проводилось.

## Ограничения
- Если файл повреждён частично, но JSON валиден (например, удалён хост), это не определяется — такой файл читается как есть.
- Нечитаемый пароль хоста (DPAPI другого пользователя или ПК) по-прежнему остаётся в поле как есть — так было и раньше.
