# LinuxOps 0.3.47 — RDP на Windows 10 1809, журнал ошибок, ширина столбцов

Дата: 2026-11-20 (МСК).

## Задача
Сообщение владельца после 0.3.46, со скриншотом v0.3.46:
1. На доменной машине (Windows 10 LTSC 2019) программа по-прежнему закрывается при **любой** попытке подключения по RDP.
2. В SSH Files не меняется ширина столбцов.
3. Вопрос: зачем программа привязана к версиям библиотек конкретной машины.

## Разбор
- **RDP.** Журнала с машины владельца нет. Что известно:
  - на этой машине (Windows 11 26100) все режимы работают;
  - падение не зависит от режима;
  - в Windows 10 1809 (сборка 17763) набор классов клиента старше.

  Программа создавала только `MsRdpClient10NotSafeForScripting`, и это создание (`new RdpControl`, `Desk.Child = rdp`) стояло вне `try`. Если такого класса нет, «класс не зарегистрирован» становится необработанным исключением, и программа закрывается при любом подключении. Это проверено на этой машине подменой класса (Debug-переключатель, см. ниже): в 0.3.46 тот же путь ронял программу.

  Библиотека типов `mstscax.dll` показывает классы MsRdpClient…MsRdpClient12. Всё нужное программе (`AdvancedSettings9`, `UpdateSessionDisplaySettings`) есть уже в `IMsRdpClient9` (Windows 8.1).
- **Столбцы.** В `Themes/Theme.xaml` у `GridViewColumnHeader` свой шаблон без `Thumb PART_HeaderGripper`, а WPF меняет ширину только через него.
- **Версии.** mstscax — это сам RDP-клиент Windows (тот же, что у mstsc). Его нельзя положить в комплект: он часть ОС и связан с CredSSP, Kerberos и политиками. Поэтому программа берёт его из системы, как mstsc, и должна подстраиваться под набор версий конкретной Windows. Comctl32 v6 — тоже системный, его подключает манифест.

## Изменения
- **`RdpControl`:**
  - класс клиента — первый зарегистрированный (проверка `HKCR\CLSID\{…}\InprocServer32`) из `MsRdpClient10`, `MsRdpClient9`;
  - если нет ни одного — понятная ошибка;
  - только Debug: `LINUXOPS_RDP_CLASS` = `9` / `none` / `broken` — проверка этих путей на машине разработчика.
- **`RdpSessionView.Connect`:**
  - создание и встраивание клиента — в `try`;
  - при ошибке клиент убирается из `WindowsFormsHost` и уничтожается. Без этого WinForms при следующей раскладке повторял ошибку своим окном «Microsoft .NET»;
  - во вкладке — причина по-русски («В этой Windows не зарегистрирован клиент RDP … Используйте «Открыть в mstsc»).
- **`Services/CrashLog`** — журнал `LinuxOps.crash.log` рядом с exe, ставится первым в `App.OnStartup`:
  - `DispatcherUnhandledException` и `System.Windows.Forms.Application.ThreadException` (режим CatchException) → запись в журнал и окно «Произошла ошибка… Программа продолжает работать»;
  - `AppDomain.UnhandledException` → запись перед закрытием;
  - векторный обработчик запоминает последнее нативное исключение (не .NET и не C++): код, модуль, для `0xC06D007E/7F` — DLL и функцию. В журнал это пишется только при падении;
  - в каждой записи — версии программы, Windows и .NET;
  - журнал ограничен 1 МБ (старый — `.old`).
- **`Themes/Theme.xaml`:** в шаблоне заголовка столбца — `Thumb PART_HeaderGripper`, тонкая линия справа, курсор ↔. Действует во всех таблицах программы.

## ✅ Проверено
Через программу, UI Automation, мышь — только при окне LinuxOps на переднем плане:
- **Клиент версии 9** (Debug, `LINUXOPS_RDP_CLASS=9`), вход по паролю на dc-01:
  - статус «dc-01 · merl@merl.loc · Обычный (пароль на сервер)»;
  - «Отключить» → «Отключено».
- **Клиента нет** (`none`):
  - во вкладке — «Не удалось создать клиент RDP: В этой Windows нет подходящего клиента…»;
  - программа работает, запись в журнале.
- **Класс есть, но не создаётся** (`broken`):
  - во вкладке — «В этой Windows не зарегистрирован клиент RDP MsRdpClient10 (mstscax)…»;
  - после изменения размера окна новых окон ошибки нет (до исправления всплывало окно WinForms «Class not registered»).
- **Регресс со штатным клиентом 10:**
  - вход по паролю — сессия и отключение;
  - RCG — окно ошибки клиента, после него статус с подсказкой, программа работает.
- **Release `dist\LinuxOps-0.3.47`:**
  - версия 0.3.47;
  - `LINUXOPS_RDP_CLASS=none` не действует (кода нет), RCG — как выше;
  - все вкладки открываются, PowerShell запускает консоль.
- **SSH Files, ширина столбцов:**
  - перетаскивание разделителя перед «Размер» на +150 px сдвинуло столбец «Размер» с x=533 на x=683, «Имя» стало шире (снимок);
  - щелчок по заголовку «Изменён» по-прежнему сортирует, программа работает.
- Сборка Debug и Release — без ошибок и предупреждений.

## 👀 Не проверено
- **RDP на машине владельца** (Windows 10 LTSC 2019) — проверка за владельцем.
  - Если причина была в классе клиента — подключение заработает.
  - Если программа всё равно закроется — причина будет в `LinuxOps.crash.log` рядом с exe: код и модуль.
  - Если будет окно «Произошла ошибка» — программа продолжит работать, текст ошибки в окне и в журнале.
- Ширина столбцов не запоминается между запусками.
- Ревью не автором не проводилось.
