# LinuxOps 0.3.34 — «Закрыть доступ» берёт учётки и ключи из аудита

Дата: 2026-11-05 (МСК).

## Задача
Пользователи, найденные аудитом, должны попадать в выпадающий список «Закрыть доступ».

## Изменения
- `Services/UserAudit.cs` — скрипт отдаёт по каждой строке `authorized_keys` сам ключ (blob), тип и комментарий (`ssh-keygen -lf -` на ключ); `UserAuditReport.Host`.
- `Services/PlanRunner.cs` — хост в отчёте аудита.
- `ViewModels/ActionsViewModel.cs` — отчёты аудита по имени хоста в памяти; передаются в `AccessWindow`.
- `AccessWindow.xaml(.cs)` — логины из аудита (UID ≥ 1000) в списке; строка «По аудиту — …» под логином; в «Отозвать ключ» — галки по ключам из аудита, отмеченные идут в поле ключа.
- `Services/ThemeManager.cs` — после установки тёмного заголовка `SetWindowPos(SWP_FRAMECHANGED)`.

## ✅ Проверено автоматически
- `dotnet build`: 0 ошибок, 0 предупреждений.
- Лаба, UI Automation без клавиатуры (дважды, второй раз на итоговой сборке): временная lo-acc с двумя ключами (один с `from="10.0.0.0/8"`) → Dry-run аудита → «Закрыть доступ»: lo-acc в списке, «По аудиту — lab-centos: 2 ключа», в «Отозвать ключ» две галки с отпечатками и комментариями → галка на втором → поле ключа заполнено → «Проверить» → «Отозвать ключ» → строка OK «ключ отозван (1 строка)». На сервере остался первый ключ с `from=`. Учётка удалена (`/home` пуст).
- Скриншот окна в тёмной теме: заголовок тёмный.

## 👀 Требует ручной проверки
- Не требуется — покрыто автопроверкой. Белый заголовок со скриншота владельца не воспроизвёлся; добавлена перерисовка рамки, проверить её на том случае нечем.
