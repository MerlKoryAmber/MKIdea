Не исправлялось:

## Найдено мной при проверке

- Окно правки после Ctrl+S не перерисовывалось — в заголовке оставался «●». Исправлено.
- Программное открытие второго файла при открытом окне правки записало бы текст первого во второй. Мышью не воспроизводится — окно перекрывает список. Исправлено: окно привязано к файлу.

- **Перетаскивание настоящей мышью не работало (нашёл владелец).** Браузер присылает `drop`, только если `dragover` отменён, а `@ondragover:preventDefault` в Blazor без своего обработчика не срабатывал. Мой тест слал `drop` событием напрямую и этого не видел. Исправлено: `dragover` отменяет скрипт страницы для дерева с `data-drop` (только Inventory), там же `setData` для Firefox. Проверено настоящей мышью во встроенном браузере: lab-178 в «Отдел Б» и обратно, аудит.
- **Files: папки вперемешку с файлами, сортировки нет (нашёл владелец).** Список шёл в порядке сервера. Теперь как в настольной версии: «..» первой, папки над файлами, щелчок по заголовку колонки — сортировка (▲/▼), папки остаются сверху.
- **После этого прошёл Files как пользователь и нашёл ещё:**
  - ввод пути + Enter откатывал путь назад — поле обновлялось по `change`, Enter читал старое значение. Исправлено (`oninput`);
  - закрытая папка (`/etc/ssh/sshd_config.d`, `/root/...`) — «Permission denied». В вебе не было списка через sudo, как «Права: sudo» в настольной. Теперь при отказе SFTP список берётся от root (те же условия, что у чтения файла через sudo: «Файлы: запись» и sudo у хоста; аудит «файлы: папка через sudo»); файлы там открываются «Изменить» и двойным щелчком, «Скачать» и «Загрузить» выключены — SFTP туда не пускает;
  - файл в закрытой папке не открывался на правку — stat через SFTP получал отказ. Теперь stat тоже от root;
  - второе сохранение такого файла спрашивало «файл изменился» — после записи размер и время не обновлялись. Исправлено;
  - подсказка в окне правки обещала копию в `~/.linuxops-bak`, а через sudo она в `~root/.linuxops-bak`. Текст поправлен.
- **Курсор в RDP отстаёт (вопрос владельца).** Курсор хоста рисовал экран сеанса по ответу сервера — с задержкой на путь туда и обратно. Теперь картинка курсора отдаётся браузеру (`Guacamole.Mouse.setCursor`, как в официальном клиенте) — он ходит за мышью сразу.
- При выкладке исправления перетаскивания проверка подключений и выкладка шли одной командой — служба перезапустилась при открытой странице владельца (192.168.0.166, без сеансов терминала). Дальше — проверка отдельно, выкладка после неё.

## 👀 Не проверено

- **Полупрод с настоящим прокси** — в лабе squid на самом стенде; на полупроде задать прокси в ⚙ и посмотреть журнал прокси.
- **«Копировать путь»** — в headless-браузере нет доступа к буферу; сработал запасной путь (путь показан в строке состояния). В обычном браузере по HTTPS должен копировать.
- **Дописывание текста во время записи** — проверено по коду и ревью; поймать окно в несколько сотен мс сценарием не удалось.
- **Курсор в RDP** — в лабе единственный Windows-хост dc-01, к нему не подключаюсь. Проверено на SSH-терминале — тот же код; на RDP посмотреть владельцу.
- **Перетаскивание в Firefox** — проверено настоящей мышью в Chromium (встроенный браузер); для Firefox добавлен `setData`, сам Firefox не проверял.
