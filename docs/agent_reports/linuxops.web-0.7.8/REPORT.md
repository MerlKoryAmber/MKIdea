# LinuxOps Web 0.7.8 — сеансы как в настольной версии, независимое ревью

Запрос владельца (23.11.2026): «делай 7.8, затем ревью и пользовательская проверка». План 0.7.8 — в `docs/linuxops/PLAN-web.md`.

Решения владельца:
- вкладки сеансов в Connections — как в настольной версии;
- предел сеансов на человека задаётся в настройках;
- PowerShell — отдельной вкладкой, одна консоль.

## Что сделано

| Область | Что |
|---|---|
| Смена вкладки шапки | History, Connections, PowerShell не пересоздаются, а прячутся. Сеансы, просмотр вживую и выбранная запись остаются. Проигрыватель встаёт на паузу. Спрятанные вкладки не перерисовываются, экран нулевого размера не меняет размер сеанса |
| Вкладки сеансов | Свой экран и своё соединение у каждой. Двойной щелчок — на вкладку хоста или новая; «Новая вкладка с этим хостом», «Дублировать сеанс», «Подключить заново», «Закрыть», «Закрыть остальные»; «lab-178 (2)»; точка состояния; × и средняя кнопка, подключённый — с вопросом |
| Предел сеансов | ⚙ → «Сеансы и записи» (раздел переименован). Проверка до пропуска и окончательно в туннеле, до подключения к guacd. Зрители не считаются. Отказ — текстом и в аудит |
| Руководства | Пользователь: раздел «Вкладки сеансов», вопрос про предел. Админ: «Сеансы и записи», предел, поведение просмотра при смене вкладки. Переснято 12 снимков, PDF пересобраны (14 и 22 стр.) |

## Независимое ревью

Два агента читали код 0.7.7–0.7.8 без моих выводов: безопасность сеансов guacd и интерфейс Blazor.

Подтверждено и **не найдено**: ввод из режима просмотра в чужой сеанс (guacd с `read-only` и фильтр `WatcherOnly`), обход прав на просмотр и записи, утечка мест под предел.

| Находка | Важность | Исправление |
|---|---|---|
| Закрытие вкладки во время подключения: в guac.js уходила освобождённая ссылка, падало всё окно (все сеансы) | критично | После каждого ожидания — проверка, что вкладка ещё есть |
| Зритель держал сеанс к хосту после ухода владельца или «Закрыть»: guacd завершает соединение только когда ушли все | важно | `LiveSession.Ended`: туннели зрителей рвутся вслед за владельцем |
| Право «Сеансы: смотреть» в своей роли открывало консоль PowerShell админа (PowerCLI) | важно | PowerShell смотреть и закрывать — только с «vCenter и PowerShell»; кнопки скрыты |
| PowerShell не перечитывал pwsh/PowerCLI после возврата на вкладку | важно | Перечитывает при возврате, фокус на консоль |
| Спрятанные вкладки перерисовывались на каждое изменение (прогон плана) | важно | `ShouldRender => Active` |
| CVE: страница прокси с кодом 200 ложилась в кэш на сутки; часть обхода JSON без проверки вида | важно | Не-JSON — сбой связи, в кэш не кладётся; весь обход через `Prop`/`Arr` |
| 👁 уходил в минус при неудачном рукопожатии зрителя | мелочь | Счёт только после `WatcherIn` |
| Нет аудита окончания просмотра; ошибка зрителя писалась как «терминал: ошибка» | мелочь | «сеанс: просмотр окончен» с длительностью; «сеанс: просмотр — ошибка» |
| `kind=gaps`: переполнение длины в испорченной записи — 500 | мелочь | Ловится, отдаётся найденное |
| Сообщение браузера в туннеле копилось без предела | мелочь | Не больше 4 МБ |
| Своё «Отключить» в первые 15 с давало «RDP: сеанс закрылся сразу» | мелочь | Закрытие помечается до вызова guac.js; guac.js при своём закрытии не шлёт состояние |
| Пауза при уходе — переключателем (могла запустить стоящую запись) | мелочь | Явная `pause` |

Не исправлялось:
- кэш пауз записи (`kind=gaps` читает весь файл при каждом открытии) — для RDP-записей в гигабайты стоит сделать позже;
- права пользователя перечитываются только при входе (как и раньше); сеанс теперь живёт до закрытия окна, обрывать — History → «Закрыть».

## Найдено мной при проверке

- **Проигрыватель «замирал» через 1–4 с (ошибка 0.7.7).** Позиция уходила в .NET дробным числом, параметр `long` — отчёт отбрасывался молча. В обычном Edge/Chrome время дробное, так что у пользователей проигрыватель не работал бы. Исправлено: целые мс.
- Отказ по пределу оставлял пустую вкладку — теперь вкладка не заводится.

## 👀 Не проверено

- **Скрытие PowerShell от своей роли с «Сеансы: смотреть»** — проверено по коду; тестовую роль заново не заводил.
- **Предел в гонке** (два окна одновременно) — окончательная проверка в туннеле прочитана, гонку не воспроизводил.
- **RDP во вкладках** — механизм тот же, что у SSH; Windows-хоста, кроме dc-01 владельца, в лабе нет.
- **Встроенная панель браузера была скрыта** — таймеры страницы там замедлены; проигрыватель проверен в headless Edge, где страница активна.
