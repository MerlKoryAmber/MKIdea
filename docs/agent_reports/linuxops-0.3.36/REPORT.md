# LinuxOps 0.3.36 — устойчивые сессии, sudo в SSH Files, мышь в терминале

Дата: 2026-11-10 (МСК).

## Задача
1) Сессии терминала и SFTP слишком быстро отваливаются. 2) «Права: sudo» в SSH Files не работает. 3) Окно SSH не реагирует на мышь — в PuTTY в mc можно щёлкать.

## Причины
1. На SSH-подключениях не было keepalive: простаивающее соединение рвали межсетевой экран или NAT. Обрыв при этом не был виден: терминал молча «замирал», SFTP падал с ошибкой на следующем действии. Лаба сама сессии не рвёт (`clientaliveinterval 0`, нет `TMOUT`).
2. Sudo в SSH Files действовал только на файловые операции. Перейти в папку, закрытую своему пользователю, было нельзя: SFTP открывает папку от имени пользователя → Permission denied.
3. Терминал не поддерживал xterm-отчёты мыши (DECSET 1000/1002/1003/1006).

## Изменения
- `Services/SshAuth.cs` — `KeepAliveInterval` 30 с для всех клиентов (терминал, SFTP, `SshRunner`).
- `ViewModels/SshTerminalViewModel.cs`, `Views/SshTerminalView.xaml.cs` — обрыв (`ErrorOccurred`, закрытие канала) → строка «Enter: подключиться снова», `Reconnect()` без очистки экрана.
- `ViewModels/SshFilesViewModel.cs` — тихое переподключение SFTP (`TryReconnect`). Просмотр папок от root (`RootList`): `find -printf` через `RunAsRoot`, режим держится, пока включён sudo. Подсказка про sudo в отказе.
- `Services/SftpBrowser.cs` — `RootListScript`, `ParseRootList`.
- `Services/TerminalScreen.cs` — режимы мыши 9/1000/1002/1003 и SGR 1006.
- `Views/TerminalCanvas.cs` — отчёты мыши: кнопки, движение, колесо, модификаторы; Shift — локальное выделение.
- `Views/SshFilesView.xaml(.cs)` — поля пути не теряют привязку при внешней установке текста и после Enter показывают текущую папку.

## ✅ Проверено автоматически
- `dotnet publish` Release: без ошибок.
- Терминал, лаба (root), UI Automation + мышь только при LinuxOps на переднем плане:
  - `printf '\e[?1002h\e[?1006h'; cat -v` → `^[[<0;10;5M ^[[<0;10;5m ^[[<64;20;6M ^[[<65;20;6M` — точные клетки щелчка и колеса;
  - mc: двойной щелчок по `.ssh` открыл `~/.ssh`, щелчок по «Quit» закрыл mc;
  - `kill -HUP $$` → «[сессия закрыта — Enter: подключиться снова]» → Enter → снова приглашение.
- SSH Files, лаба, временная учётка lo-sudo (wheel, вход по ключу):
  - без sudo `/root` → отказ с подсказкой «Права: sudo», поле пути вернулось к `/home/lo-sudo`;
  - sudo → запрос «Пароль sudo» → `/root`: `.cache … linotp-migrate, radiusproxy, .bash_history …`; `/root/.ssh` → `authorized_keys`;
  - sudo выкл → `/home/lo-sudo`;
  - `pkill -u lo-sudo -f sftp-server` на сервере + «Обновить» → «связь восстановлена», ошибки нет, список на месте.
- Учётка lo-sudo удалена, `lo-*` на лабе нет.

## 👀 Требует ручной проверки
- Keepalive против реального межсетевого экрана или NAT, который рвёт простаивающие сессии: на лабе сессии не рвутся, воспроизвести нечем. Проверка: оставить терминал и SSH Files без дела на время, за которое раньше отваливались.

## Известное ограничение
- Папку, закрытую своему пользователю, целиком не скачать: её содержимое разворачивается через SFTP. Отдельные файлы — от root, как и раньше.
