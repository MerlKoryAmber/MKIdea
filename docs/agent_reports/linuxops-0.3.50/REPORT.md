# LinuxOps 0.3.50 — «Версии ПО»: без зависаний без интернета, кэш хоста, туннель через ПК по галке

Дата: 2026-11-20 (МСК).

## Задача
Вопрос владельца: почему проверка версий может идти долго. На лабе подтвердилось: недоступный прокси — `dnf check-update` 361 с, дольше тайм-аута действия (300 с), таблицы нет вовсе. Владелец предложил проверять обновления с ПК, откуда запущена консоль, и выбрал вариант «И туннель по галке»:
- тайм-ауты и кэш — всегда;
- туннель через ПК — отдельной галкой, по умолчанию выключенной.

## Изменения
- **`Services/VersionsCheck.cs`**, шаг обновлений в скрипте:
  - сеть — не дольше 60 с (`UPD_BUDGET`):
    - dnf/yum — `--setopt=timeout=10 --setopt=retries=1` (0 у dnf/yum — «бесконечно»);
    - apt — `Acquire::http(s)::Timeout=10`, `Acquire::Retries=0`;
    - всё — под `timeout -k 5 60`;
  - не ответили — кэш хоста: `dnf -C check-update`, имеющиеся списки apt, `zypper --no-refresh lu`; updateinfo — всегда `-C`;
  - новая строка `UPATH`: путь `net` / `tunnel` / `cache` / `none`, время списков (самый свежий `repomd.xml` / `*_Packages`) и причина;
  - `UPD_PROXY` — прокси только для этой команды; dnf с ним — `--refresh` (иначе неустаревший кэш ответил бы мимо туннеля);
  - `VersionReport`: `UpdatePath`, `CacheTime`, `NetError`, `TunnelNote`, `TunnelConnections`, `TunnelLog`; текст «по репозиториям (dnf, списки от …)», «через этот ПК (туннель SSH…)», «Репозитории не ответили (…) — обновления по кэшу хоста от …».
- **`Services/PcProxy.cs`** (новый) — прокси на 127.0.0.1 ПК:
  - CONNECT и обычный HTTP, только порты 80 и 443;
  - дальше — `HttpClient.DefaultProxy` (системный прокси / PAC), на 407 — Negotiate / NTLM текущей учёткой Windows (`NegotiateAuthentication`); Basic не поддерживается;
  - журнал: число соединений, неудачи, адреса;
  - Debug: `LINUXOPS_UPSTREAM_PROXY` — адрес вышестоящего прокси или `chain` (второй такой же прокси — проверка цепочки).
- **`SshRunner.OpenRemoteForward`** — обратный проброс SSH (127.0.0.1:случайный порт хоста → прокси на ПК), до 5 попыток порта; запрет сервера — исключение с пояснением.
- **`PlanRunner`** — для `versions-check` с галкой поднимает прокси и проброс, передаёт `UPD_PROXY`, закрывает их после команды, кладёт журнал в отчёт; не поднялся — «Туннель через этот ПК не поднят: …» и обычный путь.
- **`ActionParam.Kind = "bool"`, `Hint`; `PsRunWindow`** — галка с пояснением (ИБ, SIEM / EDR, порты, учётка в журналах прокси). У «Версий ПО» — параметр `UPD_VIA_PC`, по умолчанию «нет».
- **`ActionsView`** — строка журнала туннеля под строкой об обновлениях (скрыта без галки).

## ✅ Проверено
- **Скрипт напрямую на лабе** (CentOS Stream 9):
  - обычный путь — `UPATH net` с датой списков, 4 с;
  - недоступный прокси (`UPD_PROXY=http://192.0.2.1:3128`) — 63 с вместо 361 с, `UPATH cache … нет ответа за 60 с`, обновления по кэшу те же 6.
- **Через программу (Debug, Dry-run по лабе)**:
  - окно параметров: галка выключена по умолчанию, пояснение видно (снимок);
  - без галки — 6 с, «по репозиториям (dnf, списки от 20.11.2026 17:17), с пометками безопасности», журнала туннеля нет;
  - с галкой — 16 с, «через этот ПК (туннель SSH…)», «Соединений через этот ПК: 8. Куда: mirrors.fedoraproject.org:443 ×3, mirrors.centos.org:443 ×3, repo.zabbix.com:443 ×2»;
  - с галкой и цепочкой прокси (`chain`) — 14 с, те же 8 соединений;
  - с галкой и недоступным вышестоящим прокси — 66 с, «Репозитории не ответили (нет ответа за 60 с) — обновления по кэшу хоста от …», журнал «неудачных 12», таблица версий на месте (снимок).
- После проверок на лабе нет процессов dnf и слушающих портов проброса, в `/etc/dnf/dnf.conf` прокси не появился.
- **Release `dist\LinuxOps-0.3.50`** (копия): версия 0.3.50, с галкой — 15 с, через туннель, те же 8 соединений.
- Сборка Debug и Release — без ошибок.

## 👀 Не проверено
- **Корпоративный прокси с Negotiate / NTLM** — здесь нет такого прокси; цепочка проверена только без входа.
- **Запрет проброса на сервере** (`AllowTcpForwarding no`) — настройки sshd лабы не менялись; ветка с пояснением не прогонялась.
- apt и zypper — тайм-ауты, кэш и прокси только по документации; живых Debian / SUSE нет. zypper с галкой берёт прокси из переменных окружения — уважает ли их libzypp без `/etc/sysconfig/proxy`, не проверено; если нет — журнал покажет «соединений не было».
- Как туннель видят конкретные SIEM / EDR заказчика — не проверялось.
- Ревью не автором не проводилось.
