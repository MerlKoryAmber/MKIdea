# LinuxOps 0.3.42 — вкладка PowerShell как VS Code

Дата: 2026-11-17 (МСК).

## Задача
Пользовательское тестирование вкладки PowerShell 0.3.41 (`docs/agent_reports/linuxops-0.3.41-ps-usertest/REPORT.md`) нашло 10 проблем. Кроме того, владелец не принял отдельную строку ввода («как в ISE»): «никаких отдельных полей… вместо ISE — Visual Studio Code», плюс нужны подсказки по мере набора.

Решение владельца — рекомендованное и все исправления:
- 1a — настоящий терминал: ConPTY + PSReadLine;
- 2a — PSReadLine вложить в поставку;
- 3a — подсказки в редакторе в этой же версии.

Следом — уточнение «в VS Code внизу подсказывает не так». Выбран вариант «как VS Code»: список у курсора и серый хвост из истории.

## Изменения
**LinuxOps.PsHost**
- `ConsoleMode` (`--console`): `ConsoleShell.Start` — та же консоль, что в pwsh.exe, с профилем пользователя, PSModulePath (Modules рядом с exe — первыми) и ExecutionPolicy Bypass. После профиля выполняется настройка:
  - PSReadLine: `-PredictionSource HistoryAndPlugin -PredictionViewStyle InlineView`;
  - `prompt` сообщает предиктору папку;
  - `Clear-Host` и Ctrl+L дописывают `ESC[3J` — ConPTY стирает только видимый экран, и старый вывод оставался выше при прокрутке;
  - `Out-GridView` заменён консольной функцией: таблица, с `-PassThru` / `-OutputMode` — выбор по номерам.
- `CompletionPredictor` (ICommandPredictor):
  - PSReadLine сообщает каждую правку строки;
  - предиктор в своём runspace (прогретом, с папкой консоли) считает `CompleteInput` — по последнему вводу, устаревшее отбрасывает;
  - шлёт `suggest` / `hide` по именованному каналу `--suggest <имя>`;
  - самому PSReadLine ничего не возвращает: серый хвост — только из истории.
- `PsEngine.Complete` + сообщения `complete` / `completions` — подсказки редактора.
- PSReadLine 2.3.6 (Microsoft, BSD-2) — в `Modules/PSReadLine`, копируется в `pwsh\Modules`.

**LinuxOps**
- `ConPty` — псевдоконсоль Windows: CreatePseudoConsole, пустые стандартные дескрипторы (`STARTF_USESTDHANDLES`), Resize. Закрытие убивает дерево процессов; ClosePseudoConsole вызывается в фоне.
- `PsConsoleSession`:
  - консоль: ConPTY → `TerminalScreen` (тот же эмулятор xterm, что у SSH Terminal) + канал подсказок;
  - отслеживает выход процесса (канал вывода ConPTY сам не закрывается);
  - после `exit` — «Enter: запустить снова»; есть перезапуск.
- `TerminalScreen`: режим win32-input-mode (`?9001`) — ConPTY включает его сам.
- `TerminalKeys` — клавиши в VT (перенесено из SshTerminalView) и в win32-input-mode (`ESC[Vk;Sc;Uc;Kd;Cs;Rc_`), в том числе текст и AltGr.
- `PsConsoleView`:
  - холст терминала, копирование и вставка как в Windows Terminal (Ctrl+C при выделении — копировать); многострочная вставка — одним блоком;
  - **список подсказок у курсора** (Popup, фокус остаётся в консоли): ↑↓ PgUp PgDn — выбор, Tab — вставить, Enter — вставить только после ↑↓ (иначе выполнить, как в VS Code), Esc — закрыть;
  - буквы поверх списка сужают его сразу — Tab сразу после быстрого набора не ошибается;
  - список закрывается при уходе фокуса и смене вкладки.
- `TerminalCanvas.CursorRect` — где на холсте курсор.
- `PsEditorAssist`:
  - подсказки в редакторе — по буквам с задержкой 180 мс, сразу после `- $ . : \ [`, Ctrl+Space; значок типа и описание;
  - список закрывается на не-словесном символе, поэтому Enter после `{` переносит строку;
  - Ctrl+F — поиск по-русски; автоотступ после `{` / `(`, `}` — на уровень назад; Ctrl+Z — по словам.
- `PsHighlighting` — подсветка скриптов (бывший `PsConsoleColorizer` удалён: консоль раскрашивает сам PowerShell).
- `PowerShellView` / `PowerShellViewModel`:
  - F5 — dot-source файла в консоли (несохранённый — копия в `%TEMP%\LinuxOps\PowerShell`), F8 — выделенное или строка;
  - «■ Стоп» = Ctrl+C;
  - «Перезапустить консоль» (с вопросом), «Очистить консоль» (Ctrl+L).

## ✅ Проверено
Как проверялось:
- UI Automation и настоящие нажатия клавиш: текст набирается посимвольно, кириллица тоже; ввод только при окне LinuxOps на переднем плане;
- мышь — для выделения и щелчков;
- копия Debug-сборки в scratchpad, тёмная тема; список подсказок — ещё и светлая;
- поведение `cls` — отдельной проверкой: ConPTY → `TerminalScreen` без UI.

Сценарии пользовательского теста 0.3.41 — все исправленные пункты:
- консоль запускается за 0,4–0,6 с, приглашение вверху;
- `whoami`, `cmd /c echo` с кириллицей, stderr, `git`, `ping`, `ipconfig` — вывод виден (п. 1);
- `[Console]::ReadKey()`, `pause`, Read-Host (и отмена Ctrl+C), Get-Credential — в консоли, ничего не виснет (п. 2, 9);
- Out-GridView — таблица; с `-PassThru` выбор `2` вернул вторую строку; консоль жива (п. 3);
- `cls`, `Clear-Host`, Ctrl+L и «Очистить консоль» — экран пуст, прокрутка тоже (п. 4);
- Tab дополняет, Ctrl+Space — меню (п. 5);
- Ctrl+C останавливает `Start-Sleep` за 0,6 с, «Стоп» останавливает поток вывода за 0,8 с (п. 6);
- Shift+Enter — многострочная команда `foreach` выполнилась целиком (п. 7);
- вставка трёх строк Ctrl+V — одним блоком, выполнение по Enter;
- Ctrl+F (фокус в поле поиска), автоотступ (`function Hi($name) {` ⏎ → 4 пробела), Ctrl+Z — по словам («хвост слова» → «хвост» → …) (п. 8);
- выделение мышью + Ctrl+C копирует, команда не прерывается;
- `1..20000` — 5,1 с, окно отвечает;
- `exit` → «PowerShell завершился — Enter: запустить снова» → Enter → новая консоль;
- окно 1100 px — ширина консоли 142 колонки, таблицы по ширине.

Список подсказок в консоли (сценарий `ut42s`):
- `Get-Ch` — список у курсора («Get-ChildItem» с синтаксисом), Tab → `Get-ChildItem`;
- ` -Pa` → `Path` (`[string[]] Path`), Tab → `-Path`;
- Esc закрывает только список, строка остаётся;
- быстрый набор `Get-Ch` + `il` + сразу Tab → `Get-ChildItem`;
- `whoa` — серый хвост «mi» из истории и список (`whoami.exe`); `whoami` + Enter **выполняет**, а не вставляет;
- `cd C:\Wind` → `Windows`, после `cd` — `dir .\Sys` подсказывает System, System32, SysWOW64… от новой папки;
- щелчок в редактор закрывает список.

Редактор:
- `Get-Ch` → список, Enter → `Get-ChildItem`; ` -Pa` → `-Path`;
- F5 несохранённого: «Привет, Мир», функция осталась в консоли («Привет, из консоли»);
- F8 двух строк → `q*2=6`;
- Ctrl+S → «Сохранить как» → файл, F5 по пути файла;
- закрытие программы с несохранённым — «Сохранить изменения в „q.ps1“?», «Не сохранять» — программа и все движки закрылись;
- «Перезапустить консоль» — переменные сброшены.

Найдено при проверке и исправлено:
- Ctrl+Z в редакторе **ронял программу** («No undo group should be open»): группа отмены оставалась открытой, когда ввод символа перехватывало окно подсказок;
- отмена шла по буквам: сдвиг курсора самой вставкой считался уходом из слова;
- Enter после `{` вставлял подсказку вместо переноса строки;
- Enter в консоли вставлял подсказку (`whoami` → `whoami.exe`) вместо выполнения;
- первая подсказка опаздывала: runspace предиктора прогревается при запуске;
- одного Esc не хватало, чтобы закрыть список PSReadLine перед F5/F8 — посылаются два;
- Enter после `exit` не перезапускал консоль;
- `cls` оставлял старый вывод выше в прокрутке.

Ещё:
- сборка Debug и Release (dist) без ошибок;
- smoke `dist\LinuxOps-0.3.42` (копия в scratchpad): версия 0.3.42, консоль запускается, сценарий подсказок консоли целиком — те же результаты, что на Debug.

## 👀 Не проверено
- PowerCLI / vCenter из новой консоли: лабораторного vCenter нет. Модули грузятся тем же PSModulePath, что и раньше.
- Windows 10 1809–21H2 (старый ConPTY) — проверено только на Windows 11 24H2.
- Ревью не автором не проводилось.

## Ограничения
- Подсказки (и в консоли, и в редакторе) считаются в отдельном runspace: модули и папку консоли они знают, а переменные, заданные в консоли, — нет. `$x.` для переменной консоли членов не подскажет; Tab в консоли (PSReadLine) — подскажет.
- `Start-Job` во встроенном PowerShell не поддерживается (нужен pwsh.exe) — PowerShell сам предлагает ThreadJob (`Start-ThreadJob`).
- Out-GridView — консольная замена, без окна: окно потянуло бы WPF в движок (+70 МБ), и всё равно падало (MethodAccessException).
- Read-Host и Get-Credential спрашивают в консоли, а не окнами (как в pwsh.exe). В PowerShell-действиях вкладки Actions — по-прежнему окнами.
- Ctrl+Break посылается как Ctrl+C: настоящий Ctrl+Break в PowerShell открыл бы отладчик.
