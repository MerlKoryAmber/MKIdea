# LinuxOps Web 0.2.0 — установщик и меню на сервере

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
- Владелец: установщик и CLI-меню «по аналогии с 2fa»; обновление скачивается из Git (сейчас GitHub, потом внутренний GitLab).
- Решения владельца по Ф4 (второй фактор — API MK 2FA, роли встроенные и свои, обязательный локальный админ со сбросом из меню) записаны в план (`docs/linuxops/PLAN-web.md`, решения 10–13, этап Ф0+).

## Решение
- **`deploy/install.sh`** — первая установка из распакованного релиза одной командой:
  - пакеты: nginx, firewalld, guacd из EPEL, jq, sqlite;
  - пользователь `linuxops-web`, служба, nginx с TLS, файрвол (80, 443), команда `linuxops-web`;
  - сертификата нет — выпускает свой CA сервера. CA ограничен именами и адресами этого сервера (`nameConstraints`), поэтому его безопасно добавить в «Доверенные корневые».
  - Сертификат уже есть — не трогает.
  - Старую раскладку (файлы прямо в `/opt/linuxops-web`) убирает сам.
- **Раскладка релизов:** `/opt/linuxops-web/releases/<ver>`, текущий — ссылка `current`, прежний — файл `previous`. Хранятся три версии.
- **`deploy/update.sh`:**
  - источник — `/etc/linuxops-web/release.conf`: GitHub или GitLab, адрес API, проект, префикс тега `linuxops-web-v`; токен только на чтение — в `git-token` (600);
  - режимы: последний релиз, конкретная версия, файл;
  - проверяет `.sha256`; ставит через `install.sh --upgrade` нового релиза;
  - служба не ответила за 40 с — сам возвращает прежнюю версию.
- **`deploy/uninstall.sh`:** без данных или `--purge` (два подтверждения). Бэкапы в `/var/backups/linuxops-web` не трогает.
- **Меню `linuxops-web`** — по шаблону 2fa: английские подписи, секции, номера вправо, те же действия подкомандами (`linuxops-web help`). Опасное переспрашивает.
  - Жизненный цикл: обновить (последний, версия, файл), откат, удалить, удалить с данными.
  - Доступ: токен Git (проверяется по API; не подошёл — остаётся прежний), сертификат (показать, свой CA, PEM, PFX, CSR для корпоративного CA и установка подписанного).
  - Работа: статус, старт, стоп, перезапуск, журналы (служба, аудит, nginx, guacd).
  - Данные: бэкап (база через `sqlite3 .backup`, данные, мастер-ключ, сертификат); восстановление (два подтверждения, перед ним — бэкап текущего; сертификат — отдельный вопрос).
  - Информация: адрес и проверка.
  - Каждое действие пишется в syslog (`linuxops-web`).
- **Релиз с ПК:**
  - `tools/package-linuxops-web.ps1` → `dist\LinuxOps.Web-<ver>-linux-x64.tar.gz` + `.sha256`; проверяет, что скрипты в LF;
  - `deploy/VERSION` пишет publish;
  - `tools/deploy-linuxops-web.ps1` ставит архив на стенд: первая установка или `update --file`.

## ✅ Проверено
Всё — на стенде 192.168.0.169 (AlmaLinux 10.3).
- **Переход со старой раскладки 0.1.1:** установщик убрал её, данные и мастер-ключ остались, сертификат лабы не тронут.
- **Обновление из файла** на 0.2.1; статус «0.2.1, previous 0.2.0».
- **Сломанная версия 0.2.2** (программа сразу выходит): «не ответила» → вернулась 0.2.1. «Предыдущая» осталась 0.2.0, а не сломанная. Найдено и исправлено при проверке.
- **Подменённый архив:** «checksum mismatch», установка не началась.
- **Откат из меню** (ввод через stdin, без tty): 0.2.1 → 0.2.0. Ответ «n» — отмена.
- **Источник релизов** — подставной GitHub API на стенде (тот же формат ответа):
  - «последний» взял 0.2.3, черновик 0.2.4 и чужой тег пропущены;
  - `.sha256` проверен;
  - «уже на этой версии» — без переустановки;
  - `--version 0.2.1` без `.sha256` — с предупреждением;
  - несуществующая версия и недоступный источник — понятная ошибка.
  - Пункт «токен»: файл 600, проверка по API. Найдено и исправлено: настройки источника не доходили до `update.sh`.
- **Сертификаты:**
  - CSR с доп. именем → подписан «корпоративным» CA (CA лабы) → установлен, временный ключ убран;
  - чужой ключ — «do not match», старый сертификат на месте;
  - свой CA — цепочка сходится, ограничения только на `linuxops-web` и 192.168.0.169, HTTPS 200 с этим CA;
  - PFX с паролем — с неверным паролем ошибка, с верным установлен, HTTPS 200;
  - PEM — сертификат лабы возвращён байт в байт.
- **Бэкап → удаление с данными → чистая установка → восстановление:**
  - удаление с данными, отменённое на втором вопросе, ничего не тронуло;
  - удаление с данными убрало всё, кроме бэкапов, и пользователя;
  - чистая установка выпустила свой CA;
  - восстановление вернуло мастер-ключ (тот же хэш), аудит и сертификат лабы.
- **Удаление без данных → переустановка:** ключ и база те же.
- **Записи в syslog** — по каждому шагу. HTTPS с ПК (доверие Windows) — 200.
