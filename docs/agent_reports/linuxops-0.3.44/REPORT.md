# LinuxOps 0.3.44 — RDP в приложении

Дата: 2026-11-17 (МСК).

## Задача
RDP в настольном LinuxOps. Решения владельца по наводящим вопросам:
- вкладка «Подключения» — SSH и RDP вместе, вместо SSH Terminal;
- встроенный клиент Windows (mstscax);
- пароль спрашивается при каждом подключении и живёт до закрытия вкладки;
- Remote Credential Guard по умолчанию, и это **галочка**, а не пункт выбора (уточнение владельца по ходу);
- нужны буфер обмена, размер по окну, диски и принтеры галочкой при подключении, консоль `/admin`;
- RD Gateway не нужен;
- проверка — на контроллере домена dc-01 (Exchange слишком тяжёлый).

## Изменения
- **Модель:** `WindowsHost` (IInventoryItem): имя, адрес, порт, учётка, `Auth` = rcg | restricted | password, `/admin`, диски, принтеры. Хранится в `defaults.json` (`WindowsHosts`); старые файлы читаются как раньше.
- **`AppSession`:** `WindowsHosts`; наборы ресурсов разведены:
  - `Items` — Actions (Linux + vCenter), Windows сюда не входит, логика действий не тронута;
  - `AllItems` — Inventory и папки;
  - `ConnectItems` — Linux + Windows.
- **`ResourceTree.Scope`** (All / Actions / Linux / Connect) вместо `LinuxOnly`.
- **Inventory:** кнопка и пункт меню «+ Хост Windows»; `WindowsHostEditWindow`; правка, дублирование и удаление — в `HostDialogs`.
- **«Подключения»** (`TerminalTabsView`):
  - хосты Linux и Windows в одном дереве (`HostListPanel` стал общим);
  - в одной полосе вкладок SSH и RDP;
  - открытый хост — переход на его вкладку (отключённую — переподключить без окна);
  - «+» и «Новая вкладка» — новая сессия.
- **RDP:**
  - `RdpControl` — AxHost над `MsRdpClient10NotSafeForScripting`. Свойства — поздним связыванием. События `IMsTscAxEvents` и `IMsRdpExtendedSettings` — с номерами и порядком методов, прочитанными из библиотеки типов `mstscax.dll` на этой машине.
  - `RdpSessionView` / `RdpSessionViewModel`:
    - строка состояния и кнопки «Переподключить», «Отключить», «Полный экран», «Открыть в mstsc»;
    - каждое подключение — новый экземпляр клиента;
    - размер рабочего стола следует за вкладкой (`UpdateSessionDisplaySettings`), учитываются DPI и масштаб;
    - после выхода из полного экрана размер возвращается к вкладке;
    - без сеанса область скрыта: поверх окна Windows WPF не рисует, поэтому вместо неё виден текст причины.
  - `RdpConnectWindow`: учётка, пароль, галочки RCG / Restricted Admin (одна из двух), `/admin`, диски, принтеры.
  - Настройки клиента:
    - CredSSP;
    - AuthenticationLevel 2 — предупреждение о сертификате, как в mstsc;
    - буфер обмена;
    - автопереподключение;
    - RCG — `RedirectedAuthentication` + `DisableCredentialsDelegation`; Restricted Admin — `RestrictedLogon`.
  - Причины ошибок — по-русски для частых кодов (260, 264, 516/520, 2055), остальное — текст Windows. Подсказка про Kerberos — только когда до сервера достучались.
- **Только Debug — `TestCredential`:** окно подключения заполняется из файла владельца `%LOCALAPPDATA%\LinuxOps\rdp-test.cred.xml` (Export-Clixml, DPAPI), если задана переменная `LINUXOPS_RDP_TEST_CRED`. В Release кода нет: `[Conditional("DEBUG")]` + `#if DEBUG`.
- **csproj:** `UseWindowsForms`; глобальные using WinForms и Drawing убраны (конфликты имён с WPF).
- Вкладка в меню: «SSH Terminal» → «Подключения».

## ✅ Проверено
Как проверялось:
- копия Debug-сборки, UI Automation, настоящие щелчки мыши — только при окне LinuxOps на переднем плане;
- скриншоты;
- учётка для входа — из DPAPI-файла, который владелец сохранил сам (пароль агент не вводил и не видел).

Inventory и деревья:
- «+ Хост Windows» → dc-01 сохранён в JSON (`rcg`, 3389);
- у нового хоста по умолчанию RCG включена, галочки RCG / Restricted Admin исключают друг друга;
- dc-01 есть в Inventory и «Подключениях», его нет в Actions и SSH Files.

RDP на dc-01 (Windows Server, лаба), обычный вход:
- подключение из окна, учётка подставлена, предупреждение о сертификате → вход; статус «dc-01 · учётка · Обычный»;
- окно 1500×950 — рабочий стол перестроился под вкладку (панель задач и Server Manager по ширине);
- «Полный экран» → панель подключения вверху → «Восстановить» → снова во вкладке, размер подогнан;
- «Отключить» → «Отключено»; «Переподключить» → вход **без окна** (пароль в памяти);
- повторный двойной щелчок по открытому хосту — та же вкладка, без окна;
- «+» → новая вкладка: `/admin` + диски + принтеры → «… · /admin». В сеансе в «This PC» — «Redirected drives: C on DESKTOP-…, D on DESKTOP-…». Мышь в сеансе работает (Проводник открыт и закрыт).

Ошибки (пока на dc-01 был выключен RDP):
- «dc-01.merl.loc:3389 не отвечает: удалённый рабочий стол на сервере выключен, хост выключен или порт закрыт брандмауэром» — во всех трёх режимах, без ложной подсказки про Kerberos.

Регресс:
- SSH-терминал к лабе (ВМ 2FA, `lab2fa_ed25519`) открылся в той же полосе вкладок рядом с RDP;
- вкладки Actions и SSH Files показывают только Linux.

Ещё:
- сборка Debug и Release без ошибок и предупреждений;
- smoke `dist\LinuxOps-0.3.44` (копия в scratchpad): версия 0.3.44, «Подключения» открываются.

Найдено и исправлено при проверке:
- подсказка про Kerberos показывалась и при закрытом порте;
- текст ошибки был английским и длинным.

Лаба после проверки:
- **сеанс merl на dc-01 оставлен как был.** Учётка уже работала на сервере (там открыты «Параметры → Remote Desktop», где владелец включал доступ), подключение подхватило этот сеанс. Выход из сеанса не делался, чтобы не закрыть окна владельца; RDP-клиент отключён. Открытый для проверки Проводник закрыт;
- удалённый рабочий стол на dc-01 включён владельцем для проверки — выключить ли обратно, решает владелец;
- в «Пользователи» и политики dc-01 изменений не вносилось (`DisableRestrictedAdmin` не трогали).

## 👀 Не проверено
- **Remote Credential Guard и Restricted Admin на деле.** Отсюда Kerberos к Merl.loc не работает: `nltest /dsgetdc:merl.loc` → `ERROR_NO_SUCH_DOMAIN`, нет SRV-записей `_kerberos._tcp`. Проверено только, что режим передаётся и при недоступном сервере ошибка понятная. Нужна доменная машина (или `ksetup /addkdc` — системная настройка) и `DisableRestrictedAdmin = 0` на сервере.
- Вход без пароля (SSO текущей учёткой) — по той же причине, плюс владелец работает под локальной учёткой.
- Принтеры в сеансе — галочка передаётся, сам проброс не смотрели.
- Несколько мониторов, звук — вне задачи.
- Ревью не автором не проводилось.

## Найдено попутно (не исправлялось)
- **Риск потери данных:** если `LinuxOps.defaults.json` не читается (испорчен руками), программа молча стартует пустой, а первое сохранение перезаписывает файл. Было и раньше. Предложено исправить отдельно: копия испорченного файла + предупреждение.
- **Лаба:** на 192.168.0.178 сейчас работает вторая ВМ CentOS (2FA): ключ `radiusproxy_ed25519` она не принимает, нужен `lab2fa_ed25519` (см. `~/.ssh/config`, хост `lab`). Хост lab-centos в поставочном `defaults.json` указывает на первый ключ.
