# LinuxOps Web 0.6.0 — вход: MK 2FA для AD, локальные пользователи с QR; хвосты Ф3

Дата: 2026-11-22 (МСК). Ветка `feature/linuxops-web`. Независимая проверка — по решению владельца, после выполнения плана.

## Задача
Владелец: «дальше ф3 и ф4 из плана». Хвосты Ф3 — замер нагрузки одной сессии RDP и SSH с записью, guacd и записи на SELinux enforcing. Ф4 (решение 15) — второй фактор только при входе в панель: доменные — только API MK 2FA (настройки, на живом MK 2FA не проверить), локальный админ и локальные пользователи — свой TOTP с QR-кодом (QRCoder).

## Решение
- **MK 2FA** (`MkMfa`, `LoginService.Mfa.cs`): по документу интеграции MK 2FA — `POST /challenges` → опрос → `verify` (если просят код) → `consume`; `Idempotency-Key` на каждую операцию, секрет — Bearer, хранится зашифрованным. Пускает только `consume` 200 с тем же логином (без учёта домена и регистра) и тем же `context` попытки. Ожидание — в памяти сервиса, номер — в защищённой cookie. Страница входа опрашивает `/auth/mfa/poll`; подтвердили — вход прямо в ответе. «Отмена» и уход со страницы (sendBeacon) отменяют запрос. Ошибки MK 2FA — вход закрыт, без обхода; аварийный путь — локальный админ. В ⚙ — адрес, секрет, текст в Express, «Проверить связь» (опрос несуществующего запроса: 404 — секрет принят; человеку ничего не уходит).
- **Локальные пользователи** (`LocalUser`, таблица `local_users`, `LocalUsersPanel`): пароль (PBKDF2, от 12 символов) задаёт администратор, TOTP — человек при первом входе по QR-коду. Права — назначением с пометкой `Local`: `Assignment.Matches` учитывает вид входа, поэтому назначение человеку AD не действует на локального с тем же логином и наоборот. Выбор «кому» — общий `WhoPicker` для «Назначений» и «Доступ…». TOTP админа и локальных — общий код через `ITotpAccount`.
- **SELinux:** релиз приезжал с меткой `user_tmp_t`, служба шла в `init_t`. `activate_release` делает `restorecon` релиза, данных и `/etc/linuxops-web` → `unconfined_service_t`.
- **Кэш браузера:** `app.css`, `login-mfa.js`, `guac.js` — с версией в адресе (`WebPaths.Asset`): найдено на проверке — после обновления браузер держал старый `app.css`.

## ✅ Проверено
Стенд 192.168.0.169, 0.6.0, SELinux **enforcing**; перед выкладкой — `linuxops-web backup`. Сборка Release — 0 предупреждений.
- **SELinux:** служба `unconfined_service_t` после выкладки (метки поставил установщик). SSH-сеанс с записью, RDP-сеанс с записью, отдача записи и текста терминала (200), вход AD и локальный — AVC нет. Журнал службы — без исключений.
- **Нагрузка SSH** (lab-178, root, запись включена; замер `/proc` каждые 2 с): guacd 15 → 60–75 МБ (сеанс +45–60 МБ), процессор 0–1 % при `top`; `seq 3000000` — guacd ≈ 100 % одного ядра на время потока, текст терминала 25 МБ, `.guac` 1,7 МБ. Сервис: +15 МБ, до 5 %.
- **Нагрузка RDP:** на lab-178 временно поднят xrdp (xterm с `top` и потоком текста), клиент на стенде говорит с guacd протоколом Guacamole (xrdp не умеет NLA, панель шлёт `security=nla`), запись включена, 1600×900, 80 с: guacd +85 МБ, 10–15 % ядра (до 20 %), запись 19,9 МБ, к клиенту 19,9 МБ. xrdp, учётка и порт на lab-178 после замера убраны, запись удалена.
- **MK 2FA** (заглушка API на стенде, 127.0.0.1, режимы по файлу; после проверки остановлена, MK 2FA в ⚙ выключен):
  - «Проверить связь»: неверный секрет → «отказал (401)…»; верный → «OK…». Сохранение — в аудите;
  - push: lo-dept-test → «Подтвердите вход в Express… Ждём» → подтверждено → вход; в журнале заглушки: create, 2 опроса, consume, ключи идемпотентности у POST, отмены нет;
  - код: неверный → «Неверный код.» (сообщение держится при опросе), верный → вход;
  - «Отклонить» → «Вход отклонён в MK 2FA.», «Войти снова»; поле кода и «Отмена» скрыты;
  - 403 → «…второй фактор не настроен или заблокирован. Обратитесь в поддержку.»; 503 → «MK 2FA недоступен — вход… невозможен»;
  - «Отмена» и уход со страницы → `cancel` в журнале заглушки, в аудите «вход: MK 2FA отменён».
- **Локальные пользователи** (админ, ⚙):
  - отказы формы: логин с `@`, логин `admin`, пароль короче 12, пароли не совпадают;
  - заведён `lo-local-test` → вход без назначения: отказ, в аудите «нет назначений»;
  - «Назначения» → «локальному» → «Оператор» на «Отдел Б» (🔑 в таблице); вход → QR-код и ключ → код → вход «Тест локальный · Оператор*»; Inventory — только «Отдел Б» (lab-178 не виден);
  - повторный вход: неверный код → «Неверный код…», верный → вход;
  - выключен (в базе) при открытом окне → следующий запрос — на страницу входа; «Включить», «Сбросить TOTP» → «ждёт привязки»;
  - «Доступ…» на lab-178 → «локальному» → «Просмотр» → назначение 🔑 в окне;
  - «Удалить» → вопрос в окне с числом назначений → «удалён, назначений снято: 2»; тестовые учётные данные убраны.
- Версия в шапке — 0.6.0 (`AssemblyVersion` отставал на 0.5.0 — поправлен).

## 👀 Не проверено
- **Живой MK 2FA** — доступа нет; поток проверен заглушкой по документу интеграции. Для боевого: адрес, секрет `mfa_…`, разрешённый адрес сервера, проверка из раздела 8 документа MK 2FA вместе с их командой.
- **QR-код телефоном**: картинка строится, ключ вручную и код из него работают; декодировать QR в лабе нечем (загрузка внешнего декодера в страницу запрещена).
- Ветка «consume вернул другого человека или context» — проверена чтением кода, заглушка так не отвечает.
- Нагрузка RDP — на xrdp, а не на Windows; полный прогон на 20 сеансов — на боевом сервере (по плану).
- Хвосты прежних версий: живой RDP с правом входа на dc-01, LDAPS/StartTLS, ширина окна меньше 1080 px.
