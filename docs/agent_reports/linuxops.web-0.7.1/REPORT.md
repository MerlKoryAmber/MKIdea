# LinuxOps Web 0.7.1 — исправления по независимой проверке 0.7.0

Дата: 2026-11-22 (МСК). Ветка `feature/linuxops-web`.

## Задача
Независимая проверка 0.7.0 (отдельный агент читал диф `ad5cd90..f1b9a2d`, без выводов автора): серьёзных дыр не нашла, вопрос политики — туннель «через этот ПК» доступен из API, плюс мелкие ошибки. Владелец: «Да, всё исправить».

## Решение
- **API:** `ApiJobs.ClosedParams` — `UPD_VIA_PC` скрыт в `/actions` и запрещён в `POST /jobs` (403 `param_forbidden`, в аудите). `WebStore.TouchApiClient` — время последнего запроса через `json_set` одной строкой; `UpdateApiClient` — правка по свежей копии с проверкой, что строка не поменялась (оптимистично, до 5 попыток), `AddApiClient` — без перезаписи. `PlanRunner` (ядро) — строки SKIP, FAIL выбора скрипта и DRY-RUN несут хост. Дубли адреса — одна проверка. Прерванные задания — при первом обращении к таблицам после старта (под замком, одним `UPDATE`). Счётчик отказов в аудит — общий, ограничен 10 000 ключей.
- **PowerShell:** ZIP — проверка распакованного размера по оглавлению, файлы 640; папки не трогаются (наследуют группу и setgid — см. ниже). `RemoveAll` — под тем же замком, что установка. `SafeProxy` — адрес без логина и пароля. pwsh — `NO_COLOR=1`, плюс вырезание ESC-последовательностей.
- **Установка:** профиль — путь из `PS_MOD_DIR`; `ps_sshd_check` — `sshd -T -C user=…,host=localhost,addr=127.0.0.1`.

## ✅ Проверено
Стенд 192.168.0.169, SELinux enforcing, перед каждой выкладкой — `linuxops-web backup`. Сборка Release (веб и настольная — ядро общее) — 0 предупреждений.
- **API** (учётка `svc-test` заведена в ⚙, назначение «проверка» на vm-188, запросы из браузера к `/api/v1`):
  - без назначений — 403 `no_access` три раза, в аудите одна запись;
  - `/actions` у «Версий ПО» — только `UPD_CVE`; `UPD_VIA_PC: "да"` → 403 `param_forbidden`, в аудите отказ;
  - «Проверить обновления» → done, OK «55 обновления», `connect` заполнен;
  - «Последний запрос» в ⚙ обновился (запись через `json_set` читается);
  - ⚙ «Выключить» → 401, «Включить» → 200, «Новый токен» → старый 401, новый 200;
  - задание `running` в базе + перезапуск службы → `failed`, «прервано: служба… перезапускалась»;
  - «Удалить» → назначений снято 1, заданий учётки в базе 0, учёток 0.
- **PowerShell:**
  - прокси `http://логин:пароль@127.0.0.1:9` → «Не удалось: …Connection refused», в аудите `http://***@127.0.0.1:9`, пароля в журнале нет; после правки — сообщение без цветовых кодов;
  - ZIP с тестовым модулем, файлы в архиве 0600 → «Установлено модулей: 1»; на сервере папки 2755 и файлы 640 с группой `linuxops-ps`, под учёткой консоли `Import-Module` и функция модуля работают. **Найдено на проверке:** первая версия правки делала `chmod` папкам — это снимало setgid (служба не в группе `linuxops-ps`), вложенные папки получали группу `linuxops-web`, и консоль модуль не видела; исправлено — папки не трогаются;
  - «Удалить модули» → «Удалено папок модулей: 8», статус «PowerCLI: не установлен»; «Скачать из интернета» → PowerCLI 13.5.1 снова;
  - профиль консоли — путь модулей подставлен, вход ключом сервиса работает, AVC нет;
  - `ps_sshd_check`: временный `Match Address 127.0.0.1 / DenyUsers linuxops-ps` → предупреждение «sshd (DenyUsers)…»; без него — тихо; файл убран, `sshd -t` OK.
- Тестовая учётка API и тестовый модуль после проверки удалены.

## 👀 Не проверено

- SKIP вместо FAIL для неподходящего дистрибутива — в лабе все хосты подходят действиям; ядро отдаёт хост в строке — чтением кода.
- Дубли адреса в Inventory, сбой записи задания (503), «Удалить модули» во время установки (кнопка в том же окне выключена), ZIP больше 2 ГБ в распаковке — чтением кода.
