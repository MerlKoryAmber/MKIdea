# LinuxOps 0.3.43 — sudo без пароля для учёток с ключом

Дата: 2026-11-17 (МСК).

## Задача
Владелец добавил пользователя с ключом на Debian через «Добавить пользователя» (галочка sudo, пароль пустой). При `sudo` система спросила пароль, а у учётки только с ключом пароля нет вовсе.

Причина: на Debian учётка попадала в группу `sudo`, правило которой (`%sudo ALL=(ALL:ALL) ALL`) требует пароль самого пользователя. На RHEL с группой `wheel` — то же самое.

Решение владельца:
- «sudo без пароля»;
- «ключ с паролем — третий пароль уже лишнее»: у ключа уже есть парольная фраза.

## Изменения
- `UserProvisioning`: если стоит sudo и указан ключ, то `LINUXOPS_NOPASSWD=yes`:
  - скрипт пишет `/etc/sudoers.d/linuxops-<логин>` с `<логин> ALL=(ALL) NOPASSWD: ALL` (как раньше на SUSE: `chmod 440` и `visudo -c`, при ошибке файл убирается);
  - в группу sudo/wheel учётку не добавляет.
- Без ключа всё как раньше: группа sudo/wheel (на SUSE — файл), sudo по паролю учётки.
- Если указан пароль учётки, но есть и ключ, sudo всё равно без пароля (решение владельца).
- Строка результата: «sudo без пароля добавлен» / «sudo без пароля уже есть»; в деталях `nopasswd=yes|no`.
- `AddUserWindow`: подпись галочки — «sudo (с ключом — без пароля; без ключа — по паролю учётки)».
- То же действует для «Базовых пользователей»: общий `ApplyAsync`.
- «Закрыть доступ» / «Открыть доступ» уже работают с `/etc/sudoers.d/linuxops-<логин>` — менять не пришлось.

## ✅ Проверено
Настоящий скрипт (извлечён из исходника), на лабе lab-centos (CentOS Stream 9), под root:
1. Новая учётка с ключом + sudo:
   - результат: created=yes, sudo=added, nopasswd=yes;
   - файл `-r--r-----`, учётка не в wheel, пароль заблокирован;
   - вход по ключу этой учётки, `sudo -n id -u` → `0`.
2. Повтор с теми же данными: sudo=already, key=already.
3. Без ключа, с паролем: учётка в wheel, файла нет, `sudo -n true` → «a password is required» (поведение прежнее).
4. Случай владельца — существующая учётка в группе, повторный запуск с ключом: sudo=added, nopasswd=yes, `sudo -n` по ключу → `0`.

Через программу (копия Debug-сборки, UI Automation):
- Actions → «Добавить пользователя»: логин, ключ, галочка sudo (новая подпись видна полностью) → «Добавить»;
- в результате «lab-centos — создан, sudo без пароля добавлен, ключ добавлен»;
- на хосте вход по ключу, `sudo -n id -u` → `0`.

Ещё:
- тестовые учётки и файлы sudoers удалены, `visudo -c` ок, `/etc/sudoers.d` и `/home` как до проверки; обновления не ставились;

## 👀 Не проверено
- На Debian не запускалось: в лаборатории только CentOS, WSL и Docker на машине нет.
  - Ветка «с ключом» от дистрибутива не зависит: тот же файл в `/etc/sudoers.d`.
  - В стандартном `/etc/sudoers` Debian `@includedir /etc/sudoers.d` стоит последним, поэтому наше правило перекрывает `%sudo`.
- Ревью не автором не проводилось.

## Важно
- `NOPASSWD` означает: кто владеет ключом (и знает его парольную фразу), тот получает root без дополнительного пароля. Это осознанный выбор владельца.
