# LinuxOps 0.3.40 — прокси на хостах Linux, параметры у Bash-действий

Дата: 2026-11-12 (МСК).

## Задача
Прописывать прокси на хостах Linux, в том числе для обновлений. По ходу — результат проверки прокси таблицей, как у аудита пользователей.

Согласовано: адрес прокси — параметром действия, не в Inventory (1а); менеджер пакетов + окружение по галочке (2а); прокси без логина и пароля (3б); без настоящего прокси для теста (4а). Таблица — вариант «по хосту, как у аудита». При неудачной проверке прокси остаётся прописанным (FAIL, убрать — действием) — владелец подтвердил.

## Изменения
- `Services/ProxyScripts.cs` (новый): скрипты «проверить / прописать / убрать». Только свои файлы и помеченные блоки, копия `*.linuxops.bak` перед первой правкой, dry-run — `LINUXOPS_DRY=1`, проверка обновлением списков пакетов. «Проверить» отдаёт строки с TAB (PM, R, CUR, REPO) + «Итого».
- `Services/ProxyCheck.cs` (новый): `ProxyReport` / `ProxyRow`, разбор и текстовый вид.
- `Services/BuiltinActions.cs`: `proxy-check`, `proxy-set` (параметры Proxy, NoProxy, Env), `proxy-unset`; dry-run — тот же скрипт с флагом.
- `Services/PlanRunner.cs`: параметры действия → переменные окружения (`Env`); строка proxy-check — таблица, WARN при недоступном репозитории.
- `Services/SshRunner.cs`: `IsSafeEnvName` — латиница/цифры/_, без системных имён (PATH, HOME, IFS, LD_…, BASH_…, LC_…); регистр различается.
- `Models/AppModels.cs`: `ResultRow.Proxy`.
- `ViewModels/ActionsViewModel.cs`, `Views/ActionsView.xaml`: окно параметров для Bash и PowerShell; таблица прокси в «Деталях».
- `PsRunWindow` — «Параметры действий»; `ActionEditWindow` — параметры и у Bash-действий.

## Ограничения
- dnf/yum не понимают no_proxy — для внутреннего репозитория `proxy=_none_` в его .repo (скрипт об этом пишет).
- `sudo` по умолчанию сбрасывает переменные окружения — для обновлений не важно (берут из настроек менеджера пакетов), для своих скриптов под sudo окружение прокси не действует.
- zypper: «убрать» возвращает `/etc/sysconfig/proxy` из копии целиком — правки этого файла после «прописать» пропадут.
