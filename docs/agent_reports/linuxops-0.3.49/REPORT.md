# LinuxOps 0.3.49 — «Версии ПО»: nginx, PHP… на хосте и в контейнерах

Дата: 2026-11-20 (МСК).

## Задача
Вопрос владельца: много уязвимостей в PHP, nginx и прочем — добавить во встроенные действия проверку текущих версий, в том числе в контейнерах. Предложенный план владелец принял («Да, делай»):
- опись версий на хосте и в контейнерах;
- пакеты — по репозиторию (есть ли обновление, в т. ч. безопасности);
- остальное — по сроку поддержки ветки (файл, который можно править);
- сверка с базами CVE — отложена.

## Изменения
- **`Services/VersionsCheck.cs`** — действие `versions-check`.
  - **Скрипт.** Тело — в функции `main </dev/null`: скрипт сам приходит через stdin (`bash -s`), и команда, читающая stdin, иначе съела бы его остаток.
  - **Проба версий** (POSIX sh, работает и в busybox):
    - nginx, httpd/apache2, php / php[0-9]* / php-fpm* (в т. ч. remi), openssl, OpenSSH (по sshd), mariadbd/mysqld, postgres (в т. ч. `/usr/pgsql-*`, `/usr/lib/postgresql/*`), redis-server, node, java, python3/python/python2;
    - чей файл — `rpm -qf` / `dpkg -S` / `apk info -W`;
    - повторы по `readlink -f` убираются.
  - **Обновления пакетов хоста:**
    - dnf/yum — `check-update` по найденным пакетам и `updateinfo list --updates --security`;
    - apt — `apt-get -qq update` + `apt list --upgradable` (`-security` в имени репозитория — безопасность);
    - zypper — `lu`.

    Ничего не ставится.
  - **Контейнеры docker и podman:**
    - только работающие; docker-обёртка над podman не проверяется дважды;
    - внутрь — та же проба через `exec` (`timeout 30`);
    - без оболочки — версии из переменных образа `*_VERSION`, затем из тега (имя и тег — из последней части пути, реестр с портом не мешает);
    - остановленные — только счётчиком.
  - **Разбор:** `VersionReport` / `VersionItem` / `ContainerInfo`.
  - **Оценка:**
    - пакет хоста — «обновление безопасности» (bad), «есть обновление» (warn), «актуально в репозитории» (ok); закрытая у разработчика ветка — только пояснением, т. к. исправления переносит дистрибутив;
    - контейнеры и собранное вручную — по сроку ветки.
  - **`Eol`:**
    - встроенные сроки PHP, nginx, Apache, OpenSSL, MySQL, MariaDB, PostgreSQL, Node.js, Python;
    - `LinuxOps.eol.json` рядом с exe дополняет и переопределяет их; ошибка в файле — запись в `LinuxOps.crash.log`;
    - ветка старше всех известных — «без поддержки»;
    - PHP-FPM сверяется по веткам PHP.
- **`BuiltinActions`** — карточка «Версии ПО: nginx, PHP… и контейнеры» (sudo/root — нужен для docker/podman, тайм-аут 300 с, любой дистрибутив).
- **`PlanRunner` / `ResultRow.Versions`:**
  - строка результата — WARN, если есть что обновить или ветка без поддержки;
  - превью — сводка;
  - «Детали»: текст и таблица.
- **`ActionsView` / `ActionsViewModel`** — таблица в «Деталях» (Где / Продукт / Версия / Состояние / Откуда, столбцы тянутся, цветной значок состояния, пояснение второй строкой), сводка, строка об обновлениях и контейнерах. Переключатель «Таблица / Текст» — как у аудита и прокси.

## ✅ Проверено
- **Скрипт напрямую на лабе** (CentOS Stream 9, podman 5.8, стенд 2FA — 10 контейнеров), 16 с:
  - хост: nginx 1.20.1 (nginx-core), httpd 2.4.62, PHP и PHP-FPM 8.0.30, OpenSSL 3.5.8, OpenSSH 9.9p1, Python 3.9.25 — все из пакетов, обновления найдены;
  - контейнеры: PostgreSQL 16.15, Redis 7.4.10 (alpine, файл), nginx 1.30.7 и OpenSSL 3.5.9 в 2fa_web (apk), OpenSSL 3.5.6 (dpkg, Debian 13) и Python 3.12.14 в контейнерах приложения.
- **Через программу (Debug), Dry-run:**
  - карточка в каталоге;
  - строка WARN «nginx 1.20.1, Apache httpd 2.4.62, PHP 8.0.30, PHP-FPM 8.0.30 и ещё 3 · контейнеров 10 · обновлений: 6»;
  - таблица со значками (снимок);
  - «Текст» — отчёт по хосту и контейнерам;
  - пометка «ветка 8.0 у разработчика закрыта 26.11.2023» у PHP и PHP-FPM, «ветка 1.20 … закрыта 24.05.2022» у nginx при «актуально в репозитории».
- **Release `dist\LinuxOps-0.3.49`** (копия): версия 0.3.49, отчёт и таблица те же. Как шёл этот прогон:
  - первый Dry-run на чистой копии упал на подключении SSH (тайм-аут, в копии нет файла известных ключей) — это не связано с действием;
  - отчёт получен вторым запуском — кнопкой «Применить», нажатой не тестом. Действие только читает, на лабе ничего не изменилось.
- **Разбор на образцах вывода** (запуск awk/sed на лабе, без изменений системы):
  - apt — обновления и пометка `-security`;
  - zypper — после исправления пустой строки;
  - имена пакетов из updateinfo dnf;
  - переменные образа `NGINX_VERSION` / `PHP_VERSION` / `PG_VERSION` / `MARIADB_VERSION` (эпоха и суффиксы отрезаются), теги `nginx:1.25.3-alpine`, `reg:5000/team/php:8.2-fpm`, без тега, по digest.
- Сборка Debug и Release — без ошибок.
- На лабе ничего не устанавливалось и не менялось; в контейнеры — только команды версий.

## 👀 Не проверено
- Живой Debian/Ubuntu (apt), SUSE (zypper), docker (не podman), контейнер без оболочки — только на образцах вывода.
- **CentOS Stream** публикует пометки безопасности не для всех пакетов. На лабе пометки есть (SEC 1), но к найденным пакетам не относятся — поэтому «есть обновление», а не «безопасности».
- **Сроки поддержки встроены на момент выпуска.** Для nginx 1.28/1.29 месяц закрытия (04.2026) — по выходу 1.30, точный день не указан. Сроки Redis, Java, OpenSSH не заданы — у них «нет данных».
- Kubernetes (crictl/containerd) и rootless-контейнеры других пользователей не проверяются.
- Ревью не автором не проводилось.
