# LinuxOps Web 0.3.2 — доступ из Inventory, поиск в AD, пользовательское тестирование

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
Владелец:
- «зачем при нажатии на определённые ВМ галки на папки над ними ставятся?»;
- права на папки и отдельные машины для групп — прямо из Inventory, правой кнопкой;
- «имена групп из AD я должен наизусть помнить?» — нужен поиск;
- провести пользовательское тестирование;
- убрать серое окно Blazor «Could not reconnect to the server» («ещё в admanager задолбала»).

## Решение
- **Галки дерева Actions:** состояние папки больше не выводится из хостов. Галка — только если отметили саму папку (`WebSession.CheckedFolders`); отмеченные внутри хосты — черта «частично». Снятие хоста снимает отметку с папок над ним; «Выбрать все» отмечает и папки.
- **Область роли:** `Role.Hosts` — отдельные хосты сверх `Folders`. `UserInfo.Hosts`, фильтр `ApplyFolderScope` / `InScope`: хост виден, если его папка разрешена или он сам; папки-предки — как путь.
- **Поиск AD:** `LdapAuth.Find` — bind учёткой поиска из настроек (`AdLookupUser`, пароль через `SecretBox`), фильтр по sAMAccountName / cn / displayName / description, до 25 строк. Компонент `AdPicker`: ввод с задержкой 350 мс, щелчок или Enter — выбрать, Esc или уход из поля — закрыть.
- **Inventory → правая кнопка:** меню (изменить, дублировать, хост или папка внутрь, «Доступ…», удалить). `AccessPanel`: роли с отметкой «сама / через папку / все хосты», галка сохраняет сразу; снять единственный объект роли нельзя (иначе она стала бы «все хосты»). «Дать доступ» — группа или человек из AD + шаблон прав; роль с той же группой и теми же правами дополняется, иначе создаётся.
- **Обрыв связи:** свой `#components-reconnect-modal` — полоска сверху; состояния `rejected` / `failed` → опрос `/auth/ping` раз в 2 с → `location.reload()`.
- **Найдено тестированием и исправлено:**
  - запуск по хосту без ключа: «ключ не найден: » с пустым путём → «ключ SSH не задан — укажите ключ или пароль» (ядро `SshAuth`);
  - подтверждение нового ключа хоста дольше 20 с → «Session operation has timed out». Теперь `SshRunner.Connect` повторяет подключение, если ключ за это время запомнен; таймаут — по-русски (ядро; настольная версия собрана);
  - у роли без прав правая кнопка давала меню из выключенных пунктов, двойной щелчок открывал окно правки, которое нельзя сохранить — теперь ни того, ни другого;
  - `/login` у вошедшего показывал форму входа → открывает главную;
  - History у ограниченной роли писал «всех хостов» → «по вашим хостам»;
  - список найденных групп не закрывался.

## ✅ Проверено
Стенд 192.168.0.169, 0.3.2. Браузер — SSH-туннель на `localhost`.
- **Галки:** vm-188 → «Отдел Б» и «Отдел А» с чертой; + lab-178 → обе папки с чертой; щелчок по «Отдел Б» → галка у «Отдел Б», у «Отдел А» черта; снять vm-188 → «Отдел Б» пустая; «Отдел А» → всё отмечено; ещё раз → всё снято.
- **Учётка поиска:** в AD создана `svc-lo-web` (`lab-ad`), задана в настройках; после сохранения поле пароля — «задан».
- **Поиск:** «loweb» → 5 групп GRP-LOWEB-* с OU и описанием, уже выбранная — бледная; людей «host» → lo-host-test, «dept» → lo-dept-test, выбор — плашкой; уход из поля закрывает список.
- **Доступ из Inventory:** правая кнопка по хосту → меню; «Доступ…» lab-178 — Админ/Оператор/Аудитор «все хосты», «Linux-оператор отдела» без доступа; vm-188 — у «Linux-оператор отдела» «через папку «Отдел А / Отдел Б»». Группа GRP-LOWEB-Host188 (найдена поиском) + «проверка» → создана роль «GRP-LOWEB-Host188 — проверка» с одним хостом.
- **Вход `lo-host-test`** (член GRP-LOWEB-Host188): видит «Отдел А» → «Отдел Б» → vm-188, lab-178 не видит; «Применить», «Добавить пользователя» выключены; правая кнопка — без меню, двойной щелчок — без окна.
- **Запуск под ней:** vm-188 получил тестового пользователя `lo-web` с паролем и sudo; в Inventory (admin) — User и пароль, «Проверить подключение» → вопрос о ключе хоста (отпечаток сверен с `ssh-keygen -lf` на ВМ) → «Подключено. CentOS Stream 9». Dry-run «Проверить обновления» от lo-host-test → SSH OK, 55 обновлений; в журнале службы — итог от lo-host-test.
- **Обрыв:** `systemctl restart linuxops-web` при открытой странице → полоска «переподключаюсь…», через несколько секунд страница перезагрузилась сама, пользователь остался вошедшим.
- Консоль браузера — только обрывы WebSocket от перезапусков; журнал службы после 0.3.2 — без исключений.
