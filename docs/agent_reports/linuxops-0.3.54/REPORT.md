# LinuxOps 0.3.54 — ядро вынесено в LinuxOps.Core

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
- Ф1 плана веб-версии: общая логика — в отдельный проект, чтобы веб и настольная работали на одном ядре. Для пользователя настольной ничего не меняется.

## Решение
- **`src/LinuxOps.Core`** (net8.0, без WPF). Перенесены `git mv` с сохранением истории: модели и 22 сервиса (SSH, план, каталог, «Версии ПО», CVE, обновление, учётки, прокси, история и др.). Пространства имён прежние.
- **Отвязка от Windows и WPF:**
  - окна вопросов → `IUserPrompts`, в настольной — `WpfPrompts`;
  - `CrashLog` пишет журнал, окно и нативную ловушку держит `CrashReporter`;
  - кисти → цвета строкой (`IconColor`);
  - DPAPI — только на Windows;
  - каталог данных можно задать через `LINUXOPS_DATA_DIR`.
- В настольной остались WPF, ConPTY, PowerShell, RDP.

## ✅ Проверено
- **Регресс на лабе, Debug, без `known_hosts`.** Окно «Ключ хоста» пришло через `WpfPrompts`, отпечаток сохранился. Прошли 4 действия: проверка обновлений, аудит пользователей, прокси, «Версии ПО» с CVE («закрыть сейчас: 3»).
- **Тот же регресс на Release `dist\LinuxOps-0.3.54`** (копия в scratchpad) — OK, OK, OK, WARN, CVE 3. Версия exe — 0.3.54.
- «Обновить отмеченное», «Добавить пользователя» и окна хоста — тем же кодом ядра, проверены через веб (`docs/agent_reports/linuxops.web-0.1.0`).
- Сборка решения — без ошибок.
- Данные из 0.3.53 скопированы в `dist\LinuxOps-0.3.54`, только если их там не было: defaults, history, known_hosts, кэш CVE.

## 👀 Не проверено
- **SSH Files, Подключения (SSH / RDP), PowerShell** в настольной после выноса не прогонялись. Их код остался в настольной, но они пользуются `SshRunner` и `SftpBrowser` из ядра; код этих классов перенесён без изменений. Старые UI-тесты (`files_ui`, `term_ui`) написаны под окна 0.3.2x и с нынешним интерфейсом уже не работают.
- **Окно ошибки при падении** (`CrashReporter`) не вызывалось.
