## Находки (дизайн / UX)

### P0 — нельзя догадаться без подсказки
1. **Два смысла «выбрано» у действий:** чекбокс = в план, клик по карточке = правка. Подпись в тулбаре есть, но выглядит как служебная пометка, не как UI. На макете такого дуализма нет.
2. **Footer врёт:** на Actions пишет `Inventory · хосты в defaults…` — шум, ощущение бага.
3. **Применить** визуально главный CTA всегда; рядом Dry-run вторичный — ок, но нет disabled-состояния, когда план пуст (кнопки всегда «живые»).

### P1 — визуальная иерархия
4. **Хосты / History:** нет явного row-selected (фон/рамка). Чекбокс хоста есть, «фокус строки» — нет.
5. **SSH:** `..` появился — хорошо; стрелка ↑ рядом с путём дублирует смысл — перегруз для новичка (на макете обычно одно из двух доминирует).
6. **Терминал vs списки:** зелёный term ближе к mockup-ssh; верхний chrome (чипы Inventory/Actions) с SSH-макетом не совпадает — ощущение «другой продукт в шапке».
7. **F3–F10 полоса:** выглядит чужеродно под mockup-ssh (на эталоне её нет) — либо сделать как TC-легенду плотнее, либо убрать с первого экрана.

### P2 — полировка
8. Карточки действий: теги OS мелкие «пилюли» — ок; бейдж «Встроено» ок.
9. History: таблица системная WPF, Details тёмный — стык стилей.
10. После Dry-run правая колонка «белая дыра» в одном кадре до появления строк — мигание пустоты.

## Вердикт дизайнера

Продукт **управляемый с GUI**, Connect/Dry-run работают.  
Как **визуальный продукт по макетам** — Actions и SSH всё ещё разные вселенные; главный UX-провал — **невидимое/двусмысленное выделение**. Win MessageBox убран — плюс.

## Рекомендации (по приоритету)
1. Один явный selected на карточке действия + чекбокс с подписью «В план» прямо у чекбокса.
2. Footer по режиму (уже частично; на Actions сейчас неверная строка в UT).
3. Disabled Dry-run/Применить, если 0 хостов или 0 действий в плане.
4. Inventory проверить руками (UIA toggle flaky).
5. SSH: оставить `..` или ↑ — не оба одинаково ярко.
