# LinuxOps Web 0.1.1 — стенд на AlmaLinux 10

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
- Ф0 плана: стенд на новой ВМ AlmaLinux 10, которую создал владелец («настроишь сам под себя»).
- Решения владельца: интерфейс остаётся на Blazor Server; API для сторонних сервисов нужен — внесён в план как Ф8.

## Решение
- **ВМ 192.168.0.169** (2 vCPU, 4 ГБ, 40 ГБ), AlmaLinux 10.3, ядро 6.12.0-264.17.1:
  - имя `linuxops-web`, статический адрес;
  - SELinux permissive (лаба);
  - firewalld пускает 80 и 443;
  - SSH: root только по ключу, пароли выключены.
- **Сервис** — `/opt/linuxops-web`, служба `linuxops-web` под своим пользователем, слушает 127.0.0.1:5080.
- **nginx перед сервисом:** TLS (сертификат от своего корневого CA лабы «MKIdea Lab Root CA», `linuxops-web`, `linuxops-web.lan`, 192.168.0.169), WebSocket для Blazor, 80 → 443. Конфиг — `deploy/nginx-linuxops-web.conf`.
- **Адрес клиента за прокси** — из `X-Forwarded-For`, доверие только 127.0.0.1 и ::1.
- **guacd 1.6.0** из EPEL 10 с модулями SSH и RDP, служба запущена на `[::1]:4822`.
- **Корневой CA лабы** — на стенде в `/root/lab-ca` (ключ 600), 10 лет, `pathlen:0`, ограничение по именам: 192.168.0.0/24, `*.lan`, `linuxops-web`. Сертификат стенда — 825 дней. Копия CA для «Доверенных корневых» — `dist/lab-ca/MKIdea-Lab-Root-CA.crt`.
- **graphify в MKADIdea** — как в admanager: `.graphifyignore`, граф `graphify-out/` (в git не идёт), хук `.claude/hooks/graphify-gate.ps1` не даёт искать по всему коду мимо графа.
- **Выкладка** — `tools/deploy-linuxops-web.ps1 -Target stand`: сборка → копирование → перезапуск → проверка. `/var/lib/linuxops-web` и `/etc/linuxops-web` не трогает.
- **План** (`docs/linuxops/PLAN-web.md`): nginx вместо TLS в Kestrel, стенд готов, guacd-риск снят, этап Ф8 «API для внешних сервисов» (0,7).

## ✅ Проверено
- Вход на ВМ по ключу; после перезагрузки — новое ядро, permissive, адрес .169, firewalld активен.
- Служба `active`, `https://127.0.0.1/` — 200, `http` — 301 на https, `app.css` — 200.
- Подключение Blazor (`/_blazor/negotiate`) через nginx — 200; запрос WebSocket доходит до сервиса.
- Права: `master.key` — 600, каталоги данных и ключа — 700, владелец `linuxops-web`.
- Запись «запуск … 0.1.1» — в `audit.log` и `journalctl -t linuxops-web`.
- Скрипт выкладки прогнан на стенде: служба active, https 200.
- guacd установлен и слушает 4822.
- Сертификат: `openssl verify` по CA — OK; на 443 цепочка проверяется и по имени, и по IP (`Verify return code: 0`).
- graphify: граф построен (4409 узлов), `graphify query` отвечает; хук запрещает широкий Grep и пропускает Read.
- **Браузер по HTTPS** (встроенный, после того как владелец добавил CA в «Доверенные корневые»): страница открылась без предупреждения, интерфейс работает через WebSocket. «Проверить подключение» в окне «Хост» вернуло ответ. В `audit.log` записан адрес ПК 192.168.0.168, а не 127.0.0.1. Windows строит цепочку до «MKIdea Lab Root CA» и принимает ограничения по именам.

## 👀 Не проверено
- **SELinux enforcing** — на стенде permissive; для боевого проверить в Ф3.
- Ограничение 443 по адресам рабочих машин (решение 2 плана) не сделано: в лабе пускает всех из сети.
