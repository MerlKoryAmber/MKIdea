# LinuxOps Web 0.7.6 — исправления по независимой проверке

Запрос владельца (22.11.2026): «сам проверь независимыми агентами» перед полупродом. Три агента-ревьюера разобрали 0.7.3–0.7.5:
- хранилище записей и помощник root;
- права и Inventory;
- установщик, обновление и вход.

Подтверждённые находки исправлены. Выложено на стенд (.169) и проверено там.

## Что исправлено

| Область | Находка | Исправление |
|---|---|---|
| Права | Держатель «Настроек» мог назначить себе «Админа» | Роль с админскими правами назначает и снимает только админ (⚙ «Права», «Доступ…») |
| Права | Держатель «Настроек» мог сбросить пароль, TOTP или токен учётке с ролью «Админ» и войти под ней | Такие учётки (локальные, API) меняет только админ |
| Inventory | «Проверить подключение» подставлял сохранённый ключ или пароль к любому введённому адресу | Только к тому же адресу и порту |
| Inventory | Учётка на много хостов писалась по одному; фоновые записи (подсказка дистрибутива, раскрытие папки) затирали свежую правку старой копией | Одна транзакция; фоновые записи меняют только своё поле |
| Импорт CSV | Адрес мог начинаться с «-»; длина имени и папки не ограничена; при превышении 5000 строк грузилась часть файла | Шаблон адреса; до 128 знаков; превышение — файл не грузится |
| Вход | После смены пароля прежние входы оставались | Отпечаток пароля в cookie: смена (сам, админ, сервер) закрывает все входы учётки |
| Вход | Параллельные попытки обходили предел 5 за 15 мин | Предел проверяется под замком |
| Вход | Страница входа (токен, QR и строка TOTP) могла кэшироваться | `Cache-Control: no-store` для `/`, `/login`, `/auth` |
| Хранилище | Служба могла подсунуть помощнику ссылку вместо запроса или ответа (чтение и перезапись файлов root) | Ответ — в `/run/linuxops-web-storage` (root); запрос забирается переносом и проверяется (обычный файл, владелец — служба, не ссылка) |
| Хранилище | Учётка SMB писалась по пути, который служба могла подменить | `/etc/linuxops-web` закрыт для записи службе; учётка — через временный файл и `mv` |
| Хранилище | Подключение без `nosuid,nodev,noexec`; сбой посреди подключения оставлял полусостояние; отключение могло зависнуть | Опции добавлены; ловушка ошибок возвращает прежнее; тайм-ауты, затем `-l` |
| Хранилище | Перенос и чистка могли идти одновременно; без ответа помощника перенос не начинался | Один замок; отметка «переносить с» ставится сама |
| Служба | `/etc/linuxops-web` в `ReadWritePaths`; доступ к устройствам | Убран (только чтение); `PrivateDevices=yes` |
| Установщик | `release.conf` выполнялся через `source`; при обновлении свой GitLab затирался | Разбор построчно (белый список, только `https://`); свой источник не трогается |
| Установщик | Токен в командной строке curl; уходил на чужой хост при переадресации; переадресация на http | Токен — из временного файла, только исходному хосту; только https |
| Установщик | `update --file` с относительным путём; версия не проверялась | `realpath` до `cd`; версия `^\d+(\.\d+){2,3}$` |

## 👀 Не проверено

- **Гонка неудачных входов** (предел под замком): одновременные запросы не воспроизводились, проверено чтением кода.
- **Отклонение переадресации на http и на чужой хост с токеном.** Проверено, что `http://` отклоняется. Живого источника с токеном и переадресацией на другой хост в лабе нет: проверены код и командная строка curl.
- **Подпись релизов** (рекомендация ревью) не делалась: целостность — по `.sha256` из того же источника.
