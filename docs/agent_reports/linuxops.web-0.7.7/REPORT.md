# LinuxOps Web 0.7.7 — пользовательское тестирование, наблюдение за сеансами, руководства

Запрос владельца (22.11.2026): «проведи пользовательское тестирование и сделай документацию по пользованию со скринами — например в PDF». Во время работы добавлено: запись на весь экран и кнопки управления просмотром; список идущих сеансов с просмотром и закрытием. План с вопросами согласован, ответ — «Делай».

Решения владельца:
- проигрыватель: пуск и пауза, скорость 1×–8×, пропуск простоя (галка, паузы > 5 с — до 1 с), весь экран;
- список идущих — History → Сеансы, сверху;
- права: два новых права-галки, у «Админ» — оба;
- просмотр — молча, только аудит;
- два PDF (пользователь и админ) в `docs/linuxops.web/guide`.

## Что сделано

| Область | Что |
|---|---|
| Сеансы | «Идут сейчас»: SSH, RDP, PowerShell — начало, вид, хост, кто, 👁; обновление 5 с |

| Руководства | `docs/linuxops.web/guide/`: `LinuxOps-Web-user-guide.pdf` (13 стр.), `LinuxOps-Web-admin-guide.pdf` (22 стр.), HTML-исходники, `guide.css`, 37 снимков `img/` |

Сам испорченный файл — мой тестовый из прошлой проверки, в кэше стенда исправлен |

## 👀 Не проверено

- **Живой просмотр и закрытие RDP** — проверены на SSH; RDP-сеанс владельца на dc-01 не трогал, другого Windows в лабе нет. Механизм тот же (join guacd).
- **Полноэкранный режим в настоящем браузере владельца** — во встроенной панели и в headless работает запасной вариант (окно на всю страницу); настоящий полноэкранный режим зависит от браузера.
- **Смена пароля на снимке** — у встроенного admin её нет (только меню на сервере), у тестового оператора (AD) — тоже; в руководстве описана текстом.
