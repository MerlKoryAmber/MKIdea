# LinuxOps 0.3.53 — сверка «Версий ПО» с базами уязвимостей (CVE)

Дата: 2026-11-21 (МСК).

## Задача
- **Просьба владельца.** Нужны CVE, которые надо закрывать прямо сейчас, по списку «Версий ПО» — через эти продукты заходят снаружи. Это nginx, Apache, PHP, OpenSSL, OpenSSH, MySQL/MariaDB, PostgreSQL, Redis, Node.js, Java, Python — на хосте и в контейнерах. Основной дистрибутив — CentOS (Stream).
- **Правило срочности** (согласовано: «Да, делай»): **закрыть сейчас** — CVE в CISA KEV, или EPSS ≥ 10%, или CVSS ≥ 9 по сети.
- **Вывод сокращён по замечанию владельца** («нахрена столько текста… нужно то, что срочно закрыть»). Первый вариант показывал ещё «в план» (CVSS 7–8.9), «срочных нет» / «не сверялось», описания CVE и причины — убрано: остались только срочные, по одной короткой строке.
- **Почему не порог 8 или 9.** Одной оценкой CVSS не обойтись: regreSSHion (CVE-2024-6387) — 8.1, а HTTP/2 Rapid Reset (CVE-2023-44487) — 7.5, и обе есть в KEV.

## Решение
- **`Services/CveCheck.cs`** (новый). Сверка идёт с ПК через системный прокси, синхронно после проверки версий в `PlanRunner`. Галка `UPD_CVE`, по умолчанию «да».
  - **rpm от Red Hat / CentOS / Rocky / Alma / Oracle с `.elN`** — Red Hat Security Data API:
    - список CVE исходного пакета (`cve.json?package=`) с `affected_packages`;
    - установленная сборка сравнивается по `rpmvercmp` с наибольшим исправлением для этой RHEL, эпоха не учитывается (у Stream nginx `2:`, у RHEL `1:`);
    - если исправления нет, берётся карточка CVE (`package_state`). Карточки берутся только у тех CVE, что по оценке, KEV или EPSS попадут в список. Опубликованные до выхода этой RHEL пропускаются, кроме атакуемых (KEV). На лабе так стало 177 запросов вместо 581.
  - **Сборки разработчика** (образы, nginx.org, remi, `/usr/local`) — NVD `virtualMatchString` по CPE (у nginx три CPE), с версией исправления из `versionEndExcluding`. CVE, где наш продукт не уязвим, а только «среда», отбрасываются.
  - **Пакеты Debian / Ubuntu** (`deb\d` / `ubuntu` в версии) не сверяются: исправления переносятся без смены номера. В строке пишется причина.
  - **Срочность** — CISA KEV (один файл) и EPSS (FIRST, пачками).
  - **Кэш** — сутки, `LinuxOps.cve-cache` рядом с exe. Если база не ответила, берутся старые ответы с пометкой.
  - **NVD без ключа** — один запрос за раз, пауза 6,5 с. Ключ — `LINUXOPS_NVD_API_KEY` или `LinuxOps.nvd-key.txt`.
  - **Бюджет** — 4 мин.
- **`Services/VersionsCheck.cs`**:
  - проба снимает у rpm эпоху, `SOURCERPM` и `VENDOR`, у dpkg — исходный пакет; строка `O` — дистрибутив хоста и каждого контейнера;
  - модель: `CveLevel`, `Cves`, `CveText`, `CveTop`, `CveTooltip`, `CveSummary`;
  - строки с CVE попадают в «внимание»; Format выводит список CVE по каждому продукту.
- **`PlanRunner`** — `WithCve` после «Версий ПО». Ход сверки пишется в ту же строку RUN; первая версия выводила вторую строку RUN, и та оставалась висеть над итогом.
- **`BuiltinActions`** — галка «Сверить с базами уязвимостей (CVE) — с этого ПК» с пояснением, что уходит наружу.
- **`ActionsView.xaml`**:
  - колонка «CVE» — только при срочных: красная плашка «4 CVE», под ней самая опасная; в подсказке — строка на CVE (`CVE-… · 8.1 · атака 56% · исправления нет`);
  - строка над таблицей — «Закрыть сейчас: nginx — 1, PHP/PHP-FPM — 4» (php и php-fpm из одной сборки — одной записью);
  - «Отметить безопасности» отмечает и пакеты с незакрытыми CVE.

## ✅ Проверено
- **Базы с этого ПК.** Red Hat, NVD, CISA KEV и EPSS отвечают через системный прокси. Поля API сверены вживую: `affected_packages`, `cvss3_scoring_vector`, `package_state`.
- **Лаба (CentOS Stream 9), Debug через приложение** (UI Automation, снимок), на хосте 7 продуктов и 12 контейнеров. Для проверки подняты временные контейнеры `nginx:1.25.3` и `php:8.1.2-fpm`, потом удалены вместе с образами.
  - **nginx 1.20.1-32.el9 (хост)** — 1 CVE: `CVE-2026-27654 · 8.2 · атака 28% · есть в RHEL 1.20.1-32.el9_9.1, в репо хоста нет` (Stream отстаёт от RHEL).
  - **PHP / PHP-FPM 8.0.30 (хост)** — 4 CVE, все «исправления нет», атака 13–56%.
  - **Apache, OpenSSL, OpenSSH, Python (хост)** — срочного нет, ячейка пустая.
  - **Контейнеры:** nginx 1.25.3 — 4 CVE, php 8.1.2 — 17 CVE; Redis, PostgreSQL, nginx 1.30.7 — срочного нет; openssl из Debian — не сверяется.
  - **Ложная тревога найдена и убрана** — CVE Odoo («на Python») у Python.
  - **Таблица после сокращения** (снимок): красные плашки «1 CVE» у nginx и «4 CVE» у PHP / PHP-FPM с номером под ними, у остальных пусто; над таблицей — «Закрыть сейчас: nginx — 1, PHP/PHP-FPM — 4»; одна итоговая строка WARN без висящей RUN.
- **Время.** Первая сверка (кэш пуст) — 77 с в тестовой консоли и 95 с в приложении; повторная — 5 с.
- **Release `dist\LinuxOps-0.3.53`** (копия, после сокращения вывода) — версия 0.3.53, на лабе: «Закрыть сейчас: nginx — 1, PHP/PHP-FPM — 4».
- Сборка Debug и Release — без ошибок.

## 👀 Не проверено
- **Всплывающая подсказка с полным списком CVE** — её содержимое проверено через текст «Деталей», тот же список. Само всплывание при наведении не снималось: тест без мыши.
- **Хосты Debian / Ubuntu, Rocky / Alma, модули dnf** — на лабе только CentOS Stream. Для Debian / Ubuntu и модулей сверки нет по замыслу, это написано в строке.
- **NVD с ключом** — ключа нет.
- **Светлая тема** — цвета плашек те же, что у колонки «Состояние».
- **Точность.** Если в Stream исправление пришло под другим номером сборки, чем в RHEL, возможна ложная тревога. Списки Red Hat и NVD по чужим продуктам вычищены не до конца.
- Ревью не автором не проводилось.
