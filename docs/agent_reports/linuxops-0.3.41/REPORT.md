# LinuxOps 0.3.41 — прокси: замена чужого, значения вместо переменных

Дата: 2026-11-12 (МСК).

## Задача
На реальном хосте «Прокси: проверить» показал `export http_proxy="$PROXY_URL"` вместо адреса, а «прописать» не убирал прокси, зашитый в шаблон ВМ. Владелец: показывать значения, а «прописать» — заменять чужое (на ВМ из шаблона нужен другой прокси). Поведение при неудачной проверке не меняется: прокси остаётся прописанным, FAIL.

## Изменения
- `Services/ProxyScripts.cs`:
  - «прописать» отключает чужой прокси пометкой (`#LinuxOps-disabled: `, в apt — `//LinuxOps-disabled: `): apt — общий `Acquire::http(s)/ftp::Proxy "…"` в `apt.conf` и `apt.conf.d/*` (исключения `…::Proxy::<хост> "DIRECT"` не трогаются); dnf/yum — `proxy*` в `[main]` и в `/etc/yum.repos.d/*.repo` (у репозитория прокси главнее `[main]`; `proxy=_none_` не трогается); окружение — `*_proxy=` в `/etc/environment`;
  - чужие скрипты `profile.d` не правятся (в них бывает логика) — наш файл переименован в `/etc/profile.d/zz-linuxops-proxy.sh`, выполняется последним и перекрывает их: `http/https/ftp_proxy` в обоих регистрах, `no_proxy` (пусто — `unset`), `unset all_proxy`. Старый `linuxops-proxy.sh` убирается;
  - окружение «нет» — отключённое в `/etc/environment` возвращается, о чужом прокси в `profile.d`/`environment` — предупреждение;
  - «убрать» возвращает всё отключённое и удаляет своё;
  - копия перед правкой для `apt.conf.d` — в `/var/backups/linuxops/` (apt читает все файлы папки), остальные — `*.linuxops.bak` рядом;
  - «проверить» раскрывает переменные: `$VAR` / `${VAR}` из присваиваний выше в том же файле, кавычки снимаются — в таблице `http_proxy=http://…`, строки с определением переменной не показываются. Чужие скрипты `profile.d` при нашем `zz-…` — пометка `over`.
- `Services/ProxyCheck.cs`, `Views/ActionsView.xaml`: пометка «перекрыто LinuxOps».

## Ограничения
- Значения в «проверить» раскрываются чтением файла: переменные из других файлов, `$(…)` и условия не вычисляются — такие строки показываются как есть.
- apt: прокси в блочной записи `Acquire { http::Proxy "…"; }` не распознаётся и не отключается.
- zypper: «убрать» возвращает `/etc/sysconfig/proxy` из копии целиком — правки этого файла после «прописать» пропадут.
- `sudo` по умолчанию сбрасывает переменные окружения — на обновления не влияет (берут прокси из настроек менеджера пакетов).
