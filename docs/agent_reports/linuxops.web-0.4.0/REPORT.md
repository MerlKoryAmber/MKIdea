# LinuxOps Web 0.4.0 — права как в vSphere

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
Владелец: роли ограничили хостами, а SSH, RDP, файлы, PowerShell и Inventory — все получают доступ? Обсудили и решили:
1. Модель как в vSphere: роль — набор прав, назначение — «кто → роль → объект».
2. Терминал — отдельное право (на проде учётка хоста будет не root).
3. Файлы оставить урезанно: одна панель, скачать и загрузить; права «чтение» и «запись».
4. RDP — человек входит своей доменной учёткой.
5. vCenter, PowerShell и каталог действий vCenter — только админ.
6. Закрыть дыру с папками.

«Делай и проверяй».

## Решение
- **Модель** (`AuthModels`):
  - `Role` — только `Perms`. Встроенные: Админ, Оператор, Аудитор и новая «Просмотр»; не меняются.
  - `Assignment` — `Who` (sAMAccountName), `IsGroup`, `RoleId`, `Scope` (all / folder / host), `ObjectId`.
  - `UserInfo.Grants` — роли пользователя на объекты.
  - 11 прав. `Perm.Global` (аудит, настройки, vCenter) — только из назначения на «всё»; `Perm.AdminOnly` (vCenter) в своих ролях не выдаётся.
- **Хранилище:** таблица `assignments`.
  - Перенос 0.3.x: каждая группа и человек старой роли становится назначением на «всё» (если у роли не было папок) или на каждую её папку и хост.
  - Встроенные роли из базы убраны, свои остались только с правами. Флаг `auth_model=2`.
  - Удалили папку или хост — их назначения удаляются.
- **Вход:** в cookie — группы AD (`grp`). Назначения перечитываются при открытии окна и на каждом запросе. Нет назначений — вход закрыт.
- **Проверка на объекте** (`WebSession.Access`):
  - `CanOn` — хост: «всё», сам хост, папка выше;
  - `CanOnFolder` — корень только с «всё»;
  - запуск, «Добавить пользователя», «Обновить отмеченное», опрос — по каждому хосту; не хватает права хотя бы на одном — отказ со списком;
  - хост: добавить — право на папку, менять и удалять — на сам хост;
  - папка: создать — право на родителя, переименовать — на саму, удалить — на родителя (её содержимое переезжает туда). При удалении переносятся все хосты из базы, не только видимые.
- **Интерфейс:**
  - «Доступ…» — назначения на объект: свои, от папок выше, «на всё»; «Назначить» — группа или человек и роль;
  - «Настройки» — роли (права) и общий список назначений с формой «кто — роль — на что»; «Проверить вход» показывает назначения учётки;
  - кнопки и меню Inventory — по правам на выделенный объект;
  - вкладки по правам: SSH Files — «файлы: чтение», Подключения — терминал или RDP, PowerShell — vCenter.
- **Найдено тестированием:** отказ сервиса виден только в результатах Actions, а на Inventory его не видно. Добавлено сообщение поверх любой вкладки (`WebSession.Notice`, 7 с); в тексте сказано, на что нет права.

## ✅ Проверено
Стенд 192.168.0.169, 0.4.0. Перед выкладкой — `linuxops-web backup`.
- **Перенос:** 5 старых ролей с группами → 5 назначений:
  - GRP-LOWEB-Admins → Админ на всё;
  - GRP-LOWEB-Operators → Оператор на всё;
  - lo-audit-test → Аудитор на всё;
  - GRP-LOWEB-DeptA → «Linux-оператор отдела» на «Отдел А / Отдел Б»;
  - GRP-LOWEB-Host188 → своя роль на vm-188.

  В журнале — «roles migrated to assignments (5)». У ролей остались только права.
- **«Доступ…» на «Отдел Б»:** видны своё назначение и три «на всё». Группа DeptA найдена поиском, назначен «Оператор» — запись появилась, в аудите «доступ: выдан».
- **«Назначения» в настройках:** DeptA → «Просмотр» на хост lab-178 через форму — строка в списке.
- **lo-dept-test** (DeptA: «Linux-оператор отдела» и «Оператор» на «Отдел Б», «Просмотр» на lab-178):
  - видит «Отдел А» (путь), «Отдел Б», vm-188, lab-178;
  - кнопки: на «Отдел А» — ничего; на «Отдел Б» — «+ Хост», «+ Папка», «Изменить», но не «Удалить» (нет права на родителя); на vm-188 — всё;
  - **дыра закрыта:** у «Отдел А» выключенная «Удалить» включена вручную в браузере и нажата → папка на месте, сообщение «Нет права «Inventory…»», в аудите «отказ: нет права — папка: удалить «Отдел А»»;
  - создал «Тест-подпапка» в «Отдел Б» и удалил её — работает;
  - Dry-run по vm-188 + lab-178 → отказ «Нет права «Опрос и Dry-run» на: lab-178. Снимите эти хосты.», запуска нет;
  - вкладки: Inventory, Actions, SSH Files, Подключения, History; PowerShell нет.
- **lo-audit-test** (Аудитор на всё): вкладки без «Подключений» и PowerShell, SSH Files есть; в Inventory все кнопки выключены, меню правой кнопки нет; в History есть «Аудит»; шестерёнка — только тема.
- **lo-host-test** (своя роль «просмотр, Dry-run» на vm-188): видит только путь до vm-188; вкладки Inventory, Actions, History; «Применить» выключено.
- **lo-oper-test** (Оператор на всё через вложенную группу): всё, кроме PowerShell и настроек; кнопки Inventory включены.
- **lo-admin-test** (Админ): все вкладки, включая PowerShell; шестерёнка — «тема, вход, роли».
- **svc-lo-web** (учётка AD без назначений): «У вашей учётки нет доступа к LinuxOps Web».
- Журнал службы после 0.4.0 — без исключений.
