# LinuxOps Web 0.7.0 — API только на чтение (Ф8), консоль PowerShell и PowerCLI (Ф5)

Дата: 2026-11-22 (МСК). Ветка `feature/linuxops-web`. Независимая проверка — по решению владельца, после выполнения плана (план выполнен этой версией).

## Задача
Владелец: «оба» — Ф8 (API для внешних сервисов, только действия, которые получают информацию; решение 16) и Ф5 (PowerShell и vSphere). По Ф5 решения владельца: PowerShell 7 — в релизе, PowerCLI ставит админ из ⚙ (интернет или ZIP); консоль — через guacd, как терминал.

## Решение
- **Ф8:** отдельные маршруты `/api/v1` в том же сервисе, Bearer-токен сервисной учётки (в базе — только SHA-256). Права — те же назначения, что у людей (вид входа `api`). Запускается только действие с новой пометкой ядра `ReadOnly` (и не опасное, не PowerShell), всегда dry-run; блокировка хоста, History, «Парк» и аудит — как у людей. Задание идёт в фоне, результат — опросом `/jobs/{id}`. Описание — OpenAPI 3.0.
- **Ф5:** консоль — служебная учётка ОС `linuxops-ps` с оболочкой pwsh; guacd входит по SSH на 127.0.0.1 ключом сервиса (ключ ограничен `from=`, `restrict`). Так консоль получает всё готовое у терминала: запись, текст сеанса, вставку, размер окна — без своего pty в сервисе. PowerCLI ставится в каталог модулей, который пишет сервис и читает учётка; учётка не может менять сервис и его данные.
