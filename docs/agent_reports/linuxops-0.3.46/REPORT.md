# LinuxOps 0.3.46 — RDP: Remote Credential Guard без падения и без пароля

Дата: 2026-11-18 (МСК).

## Задача
Замечания владельца после проверки 0.3.44/0.3.45 на доменной машине:
1. С галочкой Remote Credential Guard окно подключения спрашивает логин и пароль — зачем?
2. Если их не вводить, программа просто закрывается.
Вход по паролю владелец не проверял.

## Причина падения
Воспроизвёл на этой машине. Падение происходит при RCG и **любых** учётных данных — с логином и паролем тоже, как только сервер отвечает. Код выхода 0xC06D007F: функция не найдена при отложенной загрузке DLL. Исключение нативное, в `DispatchMessage`, и .NET его не ловит.

Временный перехватчик исключений (в коммит не попал) показал:
- функция — `COMCTL32.dll!TaskDialogIndirect`;
- загружен модуль `…\WinSxS\…common-controls…_5.82…\comctl32.dll`.

mstscax показывает своё окно (здесь — ошибку проверки подлинности) через TaskDialog, а он есть только в Common Controls 6. У LinuxOps не было манифеста с этой зависимостью: SDK встраивает стандартный, без неё. У mstsc.exe такой манифест есть, поэтому `mstsc /remoteGuard` работает.

В 0.3.44 RCG проверялся только при закрытом порте, до проверки подлинности дело не доходило, и падение не проявилось.

## Изменения
- **`app.manifest`** (+ `<ApplicationManifest>` в csproj): зависимость Microsoft.Windows.Common-Controls 6.0 и `asInvoker`, как в стандартном манифесте (без него Windows включила бы виртуализацию файлов). DPI-настройки не добавлялись — поведение WPF прежнее.
- **Окно подключения:**
  - галочки RCG и Restricted Admin — вверху;
  - **с любой из них полей логина и пароля нет.** Вместо них — «Вход вашей учёткой Windows: ДОМЕН\логин. Пароль не нужен и на сервер не уходит (Kerberos…)»;
  - если в Windows вход локальной учёткой (домен = имя ПК) — предупреждение, что так войти не получится;
  - сняли обе галочки — поля появляются; фокус — на логин или пароль, иначе на «Подключить».
  - В режимах RCG и Restricted Admin логин и пароль в клиент не передаются, даже если были введены до переключения.
- **Строка сессии:** вместо «текущая учётка Windows» — фактическая `ДОМЕН\логин`.
- **Причина отключения:** сервер закрыл подключение до входа (код 2/3 до LoginComplete) → «Сервер закрыл подключение до входа». Раньше было «Сеанс на сервере завершён»; подсказка про Kerberos для RCG и Restricted Admin теперь показывается и здесь.
- **Окно хоста Windows:** поле переименовано в «Учётная запись для входа по паролю», пояснения уточнены.

## ✅ Проверено
Проверял через программу: UI Automation, двойной щелчок мышью по хосту при окне LinuxOps на переднем плане. Сервер — dc-01, машина не в домене.
- **До исправления:** RCG без логина, RCG с логином, RCG с логином и паролем — программа закрывалась через 1–2 с (0xC06D007F). Restricted Admin не падал.
- **После исправления, RCG (Debug и Release `dist\LinuxOps-0.3.46`):**
  - полей логина и пароля нет;
  - видна строка с учёткой и предупреждение про локальную учётку;
  - снятие галочки показывает поля, повторная установка — прячет;
  - «Подключить» → окно клиента «An authentication error has occurred… The function requested is not supported» (то же, что у mstsc без Kerberos) → OK;
  - программа работает, статус: «Подключение не удалось (код 14087) · Remote Credential Guard работает только через Kerberos…».
- **Restricted Admin:**
  - полей нет;
  - через ~20 с статус «Сервер закрыл подключение до входа · Restricted Admin работает только через Kerberos…»;
  - программа работает.
- **Вход по паролю** (учётка из DPAPI-файла владельца, только Debug):
  - поля видны;
  - вход за ~1 с, статус «dc-01 · merl@merl.loc · Обычный (пароль на сервер)», рабочий стол во вкладке;
  - «Отключить» → «Отключено».
- **Release с новым манифестом:** все вкладки (Inventory, Actions, SSH Files, Подключения, PowerShell, History) открываются, программа отвечает. PowerShell запускает консоль: дочерние `LinuxOps.PsHost.exe` и `conhost.exe`.
- Сборка Debug и Release — без ошибок; версия Release — 0.3.46.

Лаба: сеанс merl на dc-01 — тот же, что у владельца (Server Manager, ADUC открыты). Подключился и отключился, ничего в сеансе не трогал, выход не делал.

## 👀 Не проверено
- **Вход RCG и Restricted Admin на доменной машине без пароля** — у владельца. Здесь Kerberos к Merl.loc нет. Ожидаемо:
  - RCG откроет сеанс без вопросов;
  - если сервер не разрешает режим (`DisableRestrictedAdmin` ≠ 0), появится окно клиента с ошибкой, потом статус с подсказкой.
- **Влияние Common Controls 6 на остальное.** WPF рисует сам, на его окна не влияет. Нативные окна (выбор файла, окна mstscax) теперь в современном стиле. Вкладки открываются (см. выше); SSH-подключение к лабе на этой сборке не делал — манифест к SSH не относится.
- Ревью не автором не проводилось.
