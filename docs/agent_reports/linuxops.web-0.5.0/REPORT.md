# LinuxOps Web 0.5.0 — сеансы через guacd, файлы, сводка по парку

Дата: 2026-11-21 (МСК). Ветка `feature/linuxops-web`.

## Задача
Владелец: «давай пока ф3 и ф2». Ф3 — терминал SSH и RDP через guacd с записью и проигрыванием, файлы (одна панель: скачать и загрузить, права `files.read` / `files.write`), RDP своей доменной учёткой. Остаток Ф2+ — сводка CVE по парку и проверка по расписанию. Реальная Windows в лабе — только DC (exchange не поднять: не хватит памяти).

## Решение
- **Туннель guacd** (`Services/Guac`): браузер получает только номер одноразового пропуска (60 с, тому же пользователю). Сервис сам делает рукопожатие с guacd и подставляет параметры — пароли и ключи в браузер не уходят. Сеанс — в таблицу `sessions` и в аудит (открыт, закрыт с длительностью, ошибка guacd — в статус).
- **SSH:** перед сеансом SSH.NET проверяет ключ хоста (`KnownHostsStore`, новый — вопрос в окне) и учётку. guacd (libssh2) берёт одну строку known_hosts и сам выбирает тип ключа (ECDSA раньше Ed25519). Поэтому из проверенного соединения читаются `/etc/ssh/ssh_host_*_key.pub`; им верим, только если среди них есть проверенный ключ, и отдаём ключ нужного типа.
- **RDP:** хост Windows хранится в той же таблице с меткой `DistroHint = "windows"`. Дерево, папки и права — общие, без изменения схемы. Actions, опрос, терминал и файлы такие хосты пропускают. Вход — своей учёткой; пароль только в пропуске. Параметры: NLA, `ignore-cert`, `disable-gfx`. guacd из EPEL собран на FreeRDP 2; без настоящей OpenH264 он не подключается вовсе, поэтому установщик ставит `openh264` из репозитория Cisco для EPEL (`openh264_ensure`). Ответы guacd переводятся на русский (`TerminalTab.Explain`).
- **Записи:** guacd пишет сам в `/var/lib/linuxops-web-rec` (guacd:linuxops-web, 2750 — сервис читает через группу, `DataDir` остаётся 0700). Проигрывание — `Guacamole.SessionRecording`. Текст терминала отдаётся без управляющих символов. Всё — с правом «аудит».
- **Файлы:** `SftpBrowser` получил скачивание в поток и загрузку из потока. Скачивание — одноразовая ссылка `/files/download/{id}`, поток прямо с хоста. Загрузка — `InputFile` → SFTP, до 1 ГБ, замена — с вопросом.
- **Парк:** каждый итог «Версии ПО» (`PlanProgress` теперь несёт хост) → `fleet`, только срочное. `FleetCheck` — фоновая служба: раз в сутки по всем хостам Linux, с блокировками, History и аудитом от «расписание».

- **RDP (после жалобы владельца «неправильный пароль»):**
  - причина — не пароль: в EL10 вместо OpenH264 заглушка `noopenh264`, и FreeRDP 2 в guacd бросал подключение ещё до TCP (strace — ни одного `connect` к 3389, `disable-gfx` не помогает);
  - по согласию владельца поставлена `openh264` 2.5.1 из `epel-cisco-openh264`. Cisco CDN отвечает стенду 403 — RPM скачан на ПК, подпись проверена (`rpm -K` — OK), `dnf swap noopenh264 openh264`;
  - после этого guacd доходит до DC: неверный пароль → тост «RDP: неверная учётная запись или пароль.»; верный пароль `lo-dept-test` → NLA проходит, DC закрывает сеанс → тост «RDP: пароль принят, но сервер не пустил — у учётной записи нет права входа по RDP…» (на DC у неё права нет);
  - legacy-провайдер OpenSSL не нужен — NTLM проходит без него, убран. Отладка guacd, freerdp и strace со стенда убраны;
  - по решению владельца («не делать руками — класть в дистрибутив») RPM OpenH264 — в релизе, `deploy/vendor`. Сборка скачивает его один раз и сверяет SHA-256; установщик проверяет подпись EPEL и ставит без сети;
  - проверка: на стенде возвращена заглушка `noopenh264`, репозиторий Cisco убран → выкладка: «OpenH264: openh264-2.5.1-1.el10_1.x86_64.rpm», пакет установлен; RDP снова доходит до DC — тост «пароль принят, но сервер не пустил…».
- **RDP: «чёрный экран, бегает мышь» (владелец, своя учётка):**
  - в записи сеанса guacd рисовал всё: экран приветствия, рабочий стол, Server Manager; владелец водил по нему мышью;
  - запись, проигранная тем же клиентом в отдельном блоке, показывает рабочий стол, а в окне сеанса — пусто. Причина: основной холст Guacamole с `z-index: -1` уходил под фон окна. SSH рисует в дочерний слой, поэтому не задело;

## 👀 Не проверено
- **Живой RDP-сеанс после исправления экрана** — нужен вход учёткой с правом RDP на dc-01 (у тестовой права нет, дать его на DC агенту нечем). Отображение проверено записью настоящего сеанса владельца; клавиатура и мышь в Windows — нет.
- Установка OpenH264 на чистой машине (с первой установкой guacd) не прогонялась — проверена на стенде с заглушкой. В комплекте RPM только для EL10 x86_64; на EL9 — из репозитория.
- Лицензия H.264 при распространении RPM своими силами — вопрос юристов (патентное покрытие Cisco — только для загрузки с её сервера).
- **Правая кнопка по хосту** в «Подключениях» и SSH Files — «Подключить» и «Открыть» в соседнем инструменте. ✅ Проверено после отчёта: переход с открытием хоста в обе стороны.
- Ctrl+V из настоящего буфера ПК: синтетический Ctrl+V инструмента не даёт браузеру события paste. Путь вставки проверен событием paste, есть запасной путь через `navigator.clipboard.readText`. Копирование из сеанса в буфер ПК тоже не проверено — запись в буфер в панели запрещена.
- Символы с Shift (`!`, `_`) — синтетические нажатия инструмента приходят без Shift; с настоящей клавиатуры ожидается нормально.
- Хвосты 0.3.0: LDAPS и StartTLS, MK 2FA, ширина окна меньше 1080 px (в узкой панели «History» прокручивается вбок).
